# Skill 有确定性 Script vs 无 Script 的效果对比

## 一、实验设计

| 组 | 定义 | 输入 | 允许使用的能力 |
|---|---|---|---|
| **A：无脚本** | 只加载 `SKILL.md` + `references/`，不运行任何 `scripts/` | 与 B 完全相同的原始联网检索结果 | Agent 自己读、自己筛、自己写 |
| **B：有脚本** | 同一 skill + `scripts/collect_evidence.py`、`daily_monitor.py` | 同样的原始检索结果（另做一次纯 RSS 检索作为对照） | 脚本负责抓取清洗、去重、日期过滤、打分、归类、金额解析、自动摘要、指纹与推送；Agent 负责语义判断与最终撰写 |

两个任务各做一次 A/B：①中国神华 ESG 月报；②ESG 招投标汇总 + 每日监控。
原始检索结果固化为 `data/websearch-monthly.json`（23 条）与 `data/websearch-tender.json`（13 条），保证 A/B 的“原料”一致。

**评测指标**由 `scripts/evaluate.py` 机械统计：URL 数、带日期声明数、带单位数字数、表格行数、章节数、证据引用数、主题覆盖率；另统计证据包的候选/保留/去重/低分/窗口内条数与指纹。原始结果见 `runs/compare-metrics.json` 与 `runs/compare-metrics.md`。

## 三、关键发现

### 1. 有脚本显著提升“可追溯性”和“结构化”，但代价是约 10 倍 token

B 组月报给出 17 条带 URL、带日期、带四维评分的证据，正文 86 处证据引用；A 组只有 3 个链接、0 个明确日期、无任何证据编号。招投标同理：B 有 11 个官方源链接和 66 行表格，A 只有 3 个链接、没有表格。
但 B 的字符数约是 A 的 10 倍（8,643 vs 880）。**结论**：脚本把“证据账本”的边际成本降到接近零，适合交付件；对只要三句话结论的对话场景，A 反而更经济。

### 2. 时间纪律只有脚本真正守住

A 组月报写“中证指数近期发布 V4.0”“中国神华近期获得两项奖”，把 9 月的评级方法更新和 11 月的奖项混写成“本月”；B 组证据包强制每条带日期，并把窗口外条目打上 `is_baseline`，报告因此分成“本月新增 11 条 / 存量基线 6 条”，并显式声明窗口内占比 64.7%（低于 70% 目标，主动下调结论强度）。
这类时间错位是 ESG 月报最常见也最难靠自然语言自查的错误。

### 3. 金额口径：脚本能抽取，但不能替代语义判断

招投标证据包从汇总类文章中自动抽出大量金额（S4 档 10 个、S5 档 10 个），因为一条摘要里同时出现“966 亿元、128.6 亿元、2483 万元”等多个来源级数字。这些**不是项目级中标金额**，直接统计会严重失真。
最终报告必须人工重建“数据集 A：5 笔官方中标原文（39.2/46/99/130/168 万元，中位数 99 万）”与“数据集 B/C：区间统计”的分层结构。**这是本次对比最重要的反直觉结论：高代码解决的是确定性搬运，不是口径判断。**

### 4. 纯脚本检索（无 Agent 语义检索）完全失效

`--rss` 模式用 Bing RSS 按 7 组查询抓了 38 条候选，**通过质量阈值 0 条**：大量结果跑题（查“中国神华 ESG”返回“百度网盘怎么加速”），日期缺失或与窗口不符。而同一批查询交给 Agent 的联网搜索后，23 条中 17 条通过阈值。
因此“搜索互联网 + 内容总结通过高代码实现”要拆开看：**“搜索”这一步目前仍强依赖 Agent 的语义检索；脚本高代码的价值在“搜索之后”**。把整条链路全脚本化，在当前无搜索 API Key 的条件下不可行。

### 5. 脚本自身的缺陷是被测试暴露出来的，不是靠写 skill 时能预见的

迭代过程（三次运行，指纹从 `e8ed8ce8…` → `bcf2eb7d…` → `652567b6…`）：

| 版本 | 现象 | 修复 |
|---|---|---|
| v1 | 11/23 通过；中国神华三条新闻被误判重复；评级基线被过度过滤 | 去重不能只看 URL（新闻列表页承载多条事件）；基线证据用较低阈值但打 `is_baseline` 标记 |
| v2 | 15/23 通过；仍有 2 条被误判重复；排序后重编号导致去重日志 ID 错位 | 去重条件改为“同 URL 且标题相似 或 标题相似度≥0.8”；插入时固定 ID，排序不改号 |
| v3 | 17/23 通过、0 误判、指纹可复现 | 定稿 |

这正是课程里“创建真实 Test Prompts → 与 Baseline 比较 → 检查失败案例 → 修改 → 再测试”的价值：**skill 的可靠性来自测试迭代，不来自一次写对**。

### 6. 每日监控只有脚本化才可持续

`daily_monitor.py` 已实际回放运行（模拟 2026-11-07）：13 条候选 → 昨日窗口新增 1 条 → 重点 1 条（锡东新城 130 万，官方源），输出推送文件并更新历史指纹库。A 组只能写出“可以每天搜索关键词、注意去重”的原则性描述，没有可执行产物。
在“重复、定时、需要历史去重”的任务上，脚本优势最大。

## 四、结论与选型建议

| 场景 | 推荐 | 理由 |
|---|---|---|
| 一次性、要三句话结论 | 无脚本（A） | 成本低、响应快 |
| 交付客户的报告/需审计 | 有脚本（B） | 证据链完整、时间口径可控、可复现 |
| 需要每天定时、历史去重 | 必须脚本 | 人的上下文无法跨天保留指纹库 |
| 金额/评级/口径判断 | 必须 Agent 语义判断 | 脚本只能抽取，不能判断口径 |
| 无搜索 API、纯程序抓取 | 不推荐 | 本次实测 38 条候选 0 条达标 |

**一句话总结**：Script 把 Skill 从“会说话的经验”变成“可复现的工程”；但它固化的是**流程与口径纪律**，不是**判断力**。最佳结构不是“有脚本 vs 没脚本”二选一，而是 **Agent 负责检索与判断 → 脚本负责确定性处理与留痕 → Agent 负责最终叙述**。

## 五、实验局限（必须声明）

1. **非严格双盲**：A、B 由同一 Agent 先后撰写，A 是在看到 B 的结构化输出之后写的，存在锚定效应，A 的质量可能被低估；但这也模拟了“没有脚本时 Agent 自然会用 highlights 式写法”的常见情况。
2. **token 是估算值**：按中文字符/1.5 粗估，未计入工具调用、检索结果与推理过程的真实 token；B 的额外成本实际更高。
3. **样本量小**：每个任务仅 1 次 A/B，未做多次重复来衡量随机性；脚本侧的随机性用指纹一致性验证，Agent 侧的随机性只做定性讨论。
4. **检索结果被固化**：A/B 共用同一批检索结果，未让 A 独立发起检索；真实场景中无脚本 Agent 也会自己搜索，检索成本差异未计入。
5. **评估指标偏表面**：URL 数、表格行数衡量的是“留痕程度”，不等于结论正确率；正确性依赖人工核对，已在两份报告中逐条标注来源级别与局限。

```bash
PY="/d/Program/Miniconda3/python.exe"
BASE="D:/BaiduNetdiskDownload/AI课程/Week16-Agent应用部署、Skills和OpenClaw/作业-ESG-Skill与Script对比"
S1="$BASE/作业1-两个Skill/skills/esg-monthly-report/scripts"
S2="$BASE/作业1-两个Skill/skills/esg-tender-intel/scripts"
R="$BASE/作业2-Script化与对比/runs/B-有脚本"
D="$BASE/作业2-Script化与对比/data"

# 脚本增强：证据包
"$PY" "$S1/collect_evidence.py" --config "$S1/config-monthly.json" --websearch-json "$D/websearch-monthly.json" --out "$R/evidence-monthly.json" --out-md "$R/evidence-monthly.md"
"$PY" "$S2/collect_evidence.py" --config "$S2/config-tender.json" --websearch-json "$D/websearch-tender.json" --out "$R/evidence-tender.json" --out-md "$R/evidence-tender.md"

# 纯脚本检索对照（预期 0 条通过）
"$PY" "$S1/collect_evidence.py" --config "$S1/config-monthly.json" --rss --out "$R/rss-only-monthly.json"

# 每日推送回放
"$PY" "$S2/daily_monitor.py" --config "$S2/config-tender.json" --websearch-json "$D/websearch-tender.json" --as-of 2026-11-07 --history-out "$D/history-cores.json" --out "$BASE/作业1-两个Skill/output/每日推送-回放示例-2026-11-07.md"

# 评测
"$PY" "$BASE/作业2-Script化与对比/scripts/evaluate.py" --root "$BASE/作业2-Script化与对比"
```
