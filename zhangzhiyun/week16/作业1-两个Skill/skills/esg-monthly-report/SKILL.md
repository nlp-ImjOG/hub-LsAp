# ESG 月报生成

## 目的

把"最近一个月的 ESG 信息"转化为可直接交付客户的月度报告。核心价值不在于文采，而在于**时间窗口准确、来源可追溯、客户/行业/对标三层分明、建议有证据支撑**。

## 输入与默认值

| 参数 | 说明 | 缺省值 |
|---|---|---|
| 客户 | 公司全称或简称 | 必须询问；用户说"以中国神华为例"时取中国神华 |
| 报告周期 | 起止日期 | 最近一个自然月；以执行当天倒推 31 天 |
| 行业 | 客户所属ESG重点行业 | 由客户推断，含煤炭/电力时按能源行业处理 |
| 对标企业 | 3-5 家同业 | 由行业推断，见 `references/client-shenhua-baseline.md` |
| 输出 | Markdown 文件路径 | `output/<客户>-ESG月报-<YYYY-MM>.md` |

参数缺失但可从上下文可靠推断时直接推断并在报告"口径说明"中写明；只有客户名称完全无法确定时才向用户确认。

## 执行流程

严格按 0→6 顺序执行；每一步的产物是下一步的输入。

### 0. 锁定口径

写出一行机器可读的口径声明并贯穿全程：`客户=X；窗口=YYYY-MM-DD~YYYY-MM-DD；行业=Y；对标=A/B/C`。窗口外的信息只能作为"存量基线"，不得计入"本月动态"。

### 1. 制定检索矩阵

按报告三大板块生成检索式，**每块至少 3 组、总量不少于 10 组**：

| 板块 | 检索式模板 | 重点 |
|---|---|---|
| 政策/评级/标准 | `<年份><月份> ESG 政策 发布` / `ESG 评级 方法 更新 <年份>` / `可持续发展 披露 标准 <月份>` | 官方发布、评级方法论变更、监管口径 |
| 行业新闻与最佳实践 | `<行业> ESG 最佳实践 <月份>` / `<行业> 绿色低碳 案例 <月份>` / `<行业> 社会责任 蓝皮书 <年份>` | 可复制做法、量化成效 |
| 客户动态 | `<客户> ESG <月份>` / `<客户> 可持续发展 <年份>` / `<客户> 绿色 供应链 评级 获奖 <月份>` | 本月新增事件、评级/奖项/项目 |
| 对标企业 | `<对标企业> ESG 评级 <年份>` / `<对标企业> ESG 行动 <月份>` | 同业横向可比数据 |

检索词同时准备中英文各一组；煤炭/能源行业额外加入"双碳、保供、智能化煤矿、CCUS、绿色供应链"等同义词。详细检索式与站点清单见 `references/source-priorities.md`。

### 2. 分源检索

- 用联网搜索工具执行检索矩阵，记录每组查询的**原始结果**（标题、URL、日期、摘要）。
- 优先官方源：监管机构、交易所、指数公司、行业协会、客户官网、央企采购平台；其次权威媒体；自媒体仅作线索，必须回溯到原始来源才能引用。
- 客户自身动态必须检索客户官网新闻列表页，避免只依赖二手转载。
- **脚本模式（作业2增强）**：若本 skill 的 `scripts/` 可用，先运行 `python scripts/collect_evidence.py --config scripts/config-monthly.json --websearch-json <检索结果.json> --out evidence_pack.json`，让脚本完成抓取、清洗、日期过滤、去重、打分与归类是必经步骤；本步骤产出的原始检索结果作为脚本输入。**无脚本模式**：直接在上下文中完成同样的清洗、去重、打分并人工列证据表，不得跳过打分规则。

### 3. 证据筛选与打分

对每条候选证据按 4 个维度各打 1-5 分，总分 ≥ 14 分才进入报告：

| 维度 | 5 分 | 3 分 | 1 分 |
|---|---|---|---|
| 权威性 | 监管部门/交易所/指数公司/客户官网/官方采购平台 | 权威媒体、行业主流媒体 | 自媒体、未知站点 |
| 时效性 | 窗口内且有明确发布日期 | 窗口外 3 个月内 | 时间不明 |
| 相关性 | 直接命中板块议题 | 间接相关 | 仅关键词碰巧出现 |
| 增量性 | 新发布/新变化/新数据 | 对已知事实的展开 | 旧事实重复转述 |

去重规则：标题去除标点后高度相似（字符 Jaccard ≥ 0.8）或"同一事件+同一主体+同一日期"视为同一条，保留权威性更高者，其余记入 `alts`。发现同一事实多源冲突时，按权威性排序并在报告中并列标注，不得静默择一。

### 4. 交叉验证

- 政策/标准/评级变更：至少 2 个独立来源互证，其中 1 个必须是官方原文或权威转载；无法互证时标注"单一来源，待核验"。
- 所有数字（金额、比例、排名、评级）必须能指回具体来源；不同评级机构的等级不可直接比较，必须写明机构名与评级日期。
- 区分"事实"与"观点"：专家判断、媒体解读必须写明出处与身份，不得改写成本报告的独立结论。
- 严禁幻觉：检索不到就写"本月未检索到可靠公开信息"，禁止用常识补全。

### 5. 撰写报告

按 `references/report-template.md` 的结构输出，必须包含：

1. 执行摘要（3-5 条，每条带来源编号）
2. ESG 政策、评级、标准动态
3. 客户所在行业新闻动态与最佳实践
4. 客户自身动态、ESG 影响与建议
5. 对标企业关键 ESG 行动对照表
6. 风险与关注项（含"漂绿"、范围三披露、国际规则变化等）
7. 证据清单（编号 / 标题 / 来源 / 日期 / URL / 评分）
8. 口径说明与局限性

建议必须可执行：写清"做什么、为什么、依据哪条证据"，避免"建议加强ESG管理"这类空话。以中国神华为客户时，先看 `references/client-shenhua-baseline.md` 避免把 7-10 月旧事实写成"本月新增"。

### 6. Validation（强制）

交付前逐项自检，任一项失败则回到对应步骤修复：

- [ ] 窗口内证据占比 ≥ 70%；不足则明确说明并降低结论强度
- [ ] 每条正文事实都有证据编号，证据清单中每条都有 URL 与发布日期
- [ ] 三大板块各有 ≥ 3 条证据，对标表至少 3 家企业
- [ ] 数字与评级均带机构名、日期、单位，无跨机构直接比较
- [ ] 无"本月未发生但被写成本月发生"的时间错位
- [ ] 结论不超出证据（没有把获奖等同于实质绩效提升）
- [ ] 政策类信息至少有一条官方原文链接

输出文件写入用户指定路径或默认 output 目录，并在回复中给出文件路径与 3 句话摘要。

## 异常处理

| 情况 | 处理 |
|---|---|
| 搜索结果很少 | 放宽同义词、改搜客户官网/行业媒体；仍不足则输出"信息缺口"章节，不编造 |
| 客户当月无 ESG 动态 | 明确写"本月无重大新增"，并给出最近一次可核验动态及其日期 |
| 网页抓取失败 | 改用搜索摘要，标注"摘要级证据"，并降低该条在结论中的权重 |
| 多来源数值冲突 | 并列呈现并标注口径差异，不做加权平均 |
