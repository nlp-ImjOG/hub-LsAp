# ESG 招投标情报

## 目的

把分散在政府采购网、公共资源交易中心、央企采购平台和第三方标讯站的公告，整理为**可复核的项目明细 + 热点与金额分布结论 + 可持续运行的每日增量推送**。核心风险是口径混淆：招标公告≠中标公告，预算金额≠中标金额，EPC 总额≠咨询费，必须严格分列。

## 输入与默认值

| 参数 | 说明 | 缺省值 |
|---|---|---|
| 回溯窗口 | 历史统计区间 | 执行当天倒推 2 年 |
| 赛道 | ESG / 可持续 / 双碳及其细分 | 全部六赛道 |
| 监控模式 | 历史汇总 / 每日增量 / 两者 | 两者 |
| 输出 | 报告与推送文件路径 | `output/ESG招投标情报-<YYYY-MM>.md`、`output/每日推送-<YYYY-MM-DD>.md` |

## 执行流程

### 1. 定义统计口径（先于检索）

在报告开头固定声明：窗口、`招标/中标`分别统计、金额单位统一为**万元**并保留原值、跨赛道项目按主标的归类且不重复计入合计、第三方研究机构的市场规模数据单独标注口径。

### 2. 建立检索矩阵

按"赛道 × 公告类型 × 主体类型"三维组合，至少 12 组检索式：

| 维度 | 取值 |
|---|---|
| 赛道 | 零碳园区、碳核查/碳盘查、碳足迹/产品碳标签、绿色工厂、ESG报告与评级咨询、能碳管理平台；补充：CCER、绿证、温室气体清单、碳培训 |
| 公告类型 | 招标公告、中标公告、成交结果、候选人公示 |
| 主体类型 | 央企、地方国企、政府园区、上市公司、民企 |

示例检索式：
```
"ESG 报告编制" 中标公告 2026
"零碳园区" 中标金额 2026
"碳足迹" 招标 中标 2025 2026
"能碳管理平台" 中标 万元
site:ccgp.gov.cn ESG 中标公告
"<央企名> 采购 ESG 咨询服务 中标"
```

赛道同义词、字段 schema 与金额分档见 `references/tender-taxonomy.md`；数据源可信度与检索入口见 `references/tender-sources.md`。

### 3. 采集与结构化

对每条公告抽取（缺失写"未披露"，不得猜测）：

`项目名 / 公告类型 / 发布日期 / 地区 / 业主 / 中标方 / 金额(原文+万元) / 赛道 / 来源级别 / URL / 证据摘要`

- 官方源（中国政府采购网、央企采购平台、公共资源交易中心）优先，第三方标讯站作为线索并尽量回溯原文。
- 行业统计文章（如"336份标书""437个项目"）可作为**汇总性证据**，但必须写明其采集口径与样本量，不能与逐条明细简单相加。
- **脚本模式（作业2增强）**：运行 `python scripts/collect_evidence.py --config scripts/config-tender.json --websearch-json <检索结果.json> --out evidence_pack.json`，由脚本完成金额解析、日期过滤、去重、赛道标注与分档统计。**无脚本模式**：在上下文中按同一 schema 手工完成，且必须显式列出去重前后条数。

### 4. 清洗与去重

- 同一项目"招标→中标候选人→成交公告"是同一项目的不同阶段，分析金额时只保留**中标/成交**阶段，招标阶段只用于"热点需求"统计。
- 指纹规则：业主 + 项目名核心词 + 金额（无金额时用日期）相同即去重；保留信息最完整、来源级别最高的一条，其余写入 `alts`。
- 金额换算：`X亿元 → X*10000万元`，`X万元 → X万元`，保留原值列。区间报价取上限时须标注。
- 赛道归类冲突（如"零碳园区EPC含平台"）按主标的归类，并在局限性中说明。

### 5. 分析

必须给出下列分析，每项都基于明细表而非印象：

1. **总体热度**：按季度/月的公告数量与中标数量趋势，区分招标与中标。
2. **赛道分布**：各赛道项目数、中标金额合计、金额中位数/区间；指出热点与增速（引用行业统计时写明来源）。
3. **金额分布**：按 `<10万 / 10-50万 / 50-100万 / 100-500万 / >500万` 分档统计项目数与占比；说明"EPC 亿元级 vs 咨询几十万"的量级差异，禁止混算平均单价。
4. **区域分布**：按华东/华北/华南等统计，引用区域占比时标明是营收口径还是订单口径。
5. **业主与中标方格局**：业主类型占比、头部中标机构与典型项目；区分"国家队EPC""科技龙头平台""专业咨询机构"。
6. **趋势判断**：每条判断附至少 1 条证据编号，区分"已发生"与"预测"。

### 6. 每日增量推送

配置每日监控时输出可复用方案：

- 监控源清单（购买/公开），新增查询按"昨日发布日期"过滤。
- 与历史库按项目指纹去重；只对**新增**且评分 ≥ 14 的条目推送。
- 推送格式见 `references/daily-push-template.md`，含：今日新增数、按赛道分组的标题+金额+业主+链接、与历史均价的偏离提示、无新增时的明确说明。
- 推送时间建议每个工作日 09:00；失败时保留日志并补推，不得静默跳过。
- 说明实现边界：本 skill 负责"检索策略+结构化+推送文案"，实际定时可由 automation/定时任务调用脚本完成。

### 7. Validation（强制）

- [ ] 每条明细有 URL 与发布日期；无金额写"未披露"而非 0
- [ ] 招标/中标分列，预算/成交价分列
- [ ] 去重前后条数已记录，合计未跨口径相加
- [ ] 金额单位统一为万元且原值保留，亿元已换算
- [ ] 第三方汇总数据与逐条明细分开展示
- [ ] 每个趋势判断都有证据编号
- [ ] 推送方案含去重机制与失败处理

## 异常处理

| 情况 | 处理 |
|---|---|
| 公告只有预算无中标价 | 记入需求热度，不进中标金额分布 |
| 金额区间/框架协议 | 标注区间或"框架协议，无单笔金额"，不强行取数 |
| 检索结果被第三方站截断 | 回溯官方原文；无法回溯则标"摘要级证据" |
| 同一项目多版本金额 | 以官方成交公告为准，其余写入 alts |
