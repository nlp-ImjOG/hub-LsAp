# 公告与统计口径

业务规范版本为 `esg-research-1.0`。先阅读同目录的[共同业务规范](business-rules.md)。本文件规定招投标的业务口径，JSON接口保留现有字段以支持已有数据。

入口为中国政府采购网 https://www.ccgp.gov.cn/ ，全国公共资源交易平台 https://www.ggzy.gov.cn/ ，中国招标投标公共服务平台 https://www.cebpubservice.com/ ，各省平台及采购人原站。按季度和主题搜索ESG/环境社会治理、可持续发展报告/鉴证、碳盘查/核算/核查、碳足迹、碳达峰规划、节能诊断/能碳平台，分别查中标、成交、招标、竞争性磋商、更正和终止。ESG编号、材料设备和通用政策条款的误匹配记入排除日志。

## 历史JSON

start和end为YYYY-MM-DD，表示[start,end)北京时间自然日。title、coverage、insights描述样本。records每项必需project_id、lot、title、buyer、region、category、published_at、supplier、url、verification、status。status为awarded。amount为原始数字字符串或null，unit为元/万元/亿元，currency默认CNY，amount_type为total。金额不适合统计时置null并记录note。采购人+项目编号+标包去重，重招轮次在编号中明确。

更正由研究阶段核验后，仅将有效结果传给统计脚本。project_totals可选，键为project_id，值为人民币元字符串，完整纳入一个项目全部标包时用它对账。

## 状态、身份与金额

- 查询窗口按实际最终结果首发日期过滤；本次截止日前取得的有效更正替换原结果字段并记录updated_at及原版本。更正公告明确重新作出定标决定时，说明采用的新结果日期。存在窗口内外冲突且未解决时列待核验。
- 标题中的中标字样需结合正文确认。候选人/拟成交、尚待公示期结束的条件性结果、备选供应商、框架入围和最终中标分别记录；主备报价不能叠加计算。
- 标包主键为采购人身份、项目编号、标包编号。项目主键为采购人身份加项目编号，项目数、项目金额、集中度、对账和供应商分布均沿用该身份。采购人简称需有证据映射后再合并。
- 跨站URL和抓取时间差异作为来源元数据合并。成交金额、最终供应商或状态有实质冲突时，先查有效更正；未解决的冲突包列待核验。项目编号缺失时使用明确标注的临时名称键并人工查重。
- 重招轮次分别记录，并关联已废标/终止的前轮；同一轮多次转载合并。多标包公告只将实质相关且可核验的标包纳入，说明未纳入部分。
- 成交总价保留原币种及单位。缺失总价、单价、折扣、框架上限或外币换算未确定时，保留公告条目并说明金额缺口；人民币总价分布仅采用有效且可比较的金额。预算和代理费保留各自字段。
- 金额缺失率用缺少可统计总价的标包数除以纳入标包数，另列币种、费率等导致不可比的数量。多年服务采用原合同总价，年度等价分析需另说明服务期和假设。
- 完整项目的标包合计与同范围项目总价对账。公告总额覆盖不相关标包或只取得部分包时，注明部分覆盖并保留未纳入差额。概要、正文与附件金额冲突先查更正，不能仅挑选其中一个金额。
- 索引正文必须包含身份、状态、日期和所采用金额的必要上下文并标注。结果中分别展示包含索引正文的完整样本和直接原文/官方镜像子样本，说明结论是否受证据等级影响。

## 日报状态业务表

先核对最新已知更正/撤销及时间字段的一致性，获取结束早于获取开始、投标截止早于公告发布等冲突列待核验。时刻不详且影响当时可参与性的日期保留精度并列待核验。

| 条件 | 报告状态与表述 |
| --- | --- |
| 已有撤销或终止依据 | 撤销/终止，保留公告版本 |
| 已核实投标截止不晚于判断时点 | 已截止；后续延期需有已知有效依据 |
| 关键日期缺失、冲突或未核对有效更正 | 期限/状态待核验 |
| 获取开始晚于判断时点，投标仍未截止 | 文件获取尚未开始 |
| 获取结束早于判断时点，投标仍未截止 | 已获取文件者可跟进，注明资格与最新公告核验情况 |
| 获取开始、结束和投标截止均完整，且判断时点位于有效获取期内 | 文件获取期内；具体参与资格按已核验情况说明 |
| 发布方明确允许直接下载、无单独获取起点要求 | 保存该原文依据后按实际安排判断 |

资格未完整取得时写明具体待核验项。项目匹配度、文件获取可行性和已满足资格分别表达。撤销/截止可凭相应充分证据判定，其余状态受缺失字段约束。获取期结束边界以发布方精度和规则为准。

更正补查覆盖本次入选机会，并检查截止临近的既有机会。相同业务主键的同一版本只新增展示一次；版本变化记录变更原因。last_success_at表示成功检索截止时点，seen表示本地展示，外发投递另记回执。

## 现有脚本与业务规范的核对

本次统一业务规则，现有脚本有两处已复现的实现差异，需要在后续代码阶段修正。

- analyze.py项目金额按project_id单独汇总，跨采购人同编号时会合并集中度。交付前用采购人加项目编号独立复核集中度与项目对账；涉及碰撞时修正展示并说明复核方式。
- analyze.py缺少acquisition_start时可能给出可新参与分组。日报按上表复核并修正HTML中的状态，缺失起点的情形需要明确的无获取起点要求依据或列待核验。

规则修订与脚本实现分别验收，后续实现通过相应场景验证后更新本节。

## 日报JSON

title、as_of、window_start、coverage、records。时间字段为带+08:00的ISO时间。每条包含project_id、lot、buyer、title、url、published_at、deadline、acquisition_start、acquisition_end、version、status、budget_text、scope、qualification、remarks。deadline/acquisition_end可null，缺失时判待核验。获取开始时间已知时记录acquisition_start，用于识别尚未开放。version为真实公告更新时间或内容哈希，更正时变化。status取open/cancelled。资格需保留中小企业、联合体及特定要求。

更正公告保存updated_at（带时区的实际更新时间），日报按updated_at优先判断是否落入检索窗口，原published_at保留首发时间。状态文件记录已在本地HTML展示的项目版本，在HTML写入成功后原子更新。独占锁避免同时使用同一状态。重复版本不再展示，重新回放用独立state。正式推送另需发送回执及幂等键。

## 报告口径

项目与标包分别计数，联合体每包计一次。金额缺失计入缺失率。图表从records计算，桶为[0,50万)、[50万,100万)、[100万,300万)、[300万,+∞)。零样本正常输出。样本量、来源偏向、多年服务总价、单个项目多包集中应显著注明。报告支持读者从明细回查公告。

JSON另保存business_rules_version、metadata、sources、access_failures、excluded_or_pending及quality_checks，查询日志逐条留存。业务验收检查日期/状态/金额、标包与项目身份、金额分桶和合计、缺失率、索引证据敏感性、跨次展示及关键缺口。重要限制与复核结果同时进入HTML可见正文。
