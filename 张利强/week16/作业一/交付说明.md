# 交付说明

本目录交付两个 OpenCode Skill：`esg-monthly-report`（中国神华 ESG 月度简报）与 `esg-bid-monitor`（ESG 招投标信息监控）。两个 Skill 都是自包含的：`SKILL.md` 负责编排流程，`agents/` 放各阶段提示词，`templates/` 放输出模板，`scripts/` 放可运行的 Python 工具。设计文档与实现计划在 `skill/esg-skills-design/`。

## 2. 如何加载

方式一（本目录内）：

```bash
cd 张利强/week16/作业一
opencode
```

`opencode.json` 声明 `"skills": ["./skill/esg-skills"]`，OpenCode 会把该目录下的两个子目录识别为 Skill。

方式二（拷走单个 Skill）：把 `skill/esg-skills/esg-monthly-report/` 或 `skill/esg-skills/esg-bid-monitor/` 整个目录复制到 OpenCode 的 skills 目录即可，两个 Skill 不互相依赖。共用脚本各自持有一份副本，复制后仍可独立运行。

## 3. 触发示例

ESG 月报：

- “生成 2026 年 11 月的中国神华 ESG 月报”
- “汇总上个月的 ESG 政策和行业动态”
- “做一份 ESG 月度简报，对标几家同行”
- “Generate the China Shenhua ESG monthly brief for 2026-11”

招投标监控：

- “汇总近两年 ESG 和双碳相关的招标、中标信息”
- “每天推送 ESG 招投标新增标讯”
- “看看最近的环保项目招标金额分布”
- “Monitor ESG tender notices and push new awards daily”

月报必须提供 `target_month`（`YYYY-MM`），缺失时 Skill 会先询问，不会自行猜测“最近一个月”。

## 4. 环境与依赖

- Python 3.12（本机使用 conda 环境 `py312`）。
- 第三方库见 `requirements.txt`：`requests`、`reportlab`、`pandas`、`matplotlib`。
- 检索密钥：

```bash
export DEEPSEEK_API_KEY="<your-key>"
```

`search_deepseek.py` 请求 `https://api.deepseek.com/v1/tools/search`。未配置密钥时不发请求，打印错误并以退出码 2 结束；这是刻意的失败路径，避免用模型记忆代替检索。

安装依赖：

```bash
conda run -n py312 pip install -r requirements.txt
```

## 5. 常用命令

```bash
# 检索（月报、招投标共用）
conda run -n py312 python skill/esg-skills/esg-monthly-report/scripts/search_deepseek.py \
  --query "ESG 政策" --start 2026-11-01 --end 2026-11-30 \
  --site gov.cn --limit 20 --output /tmp/policy.json

# 月报校验：有违规退出 1，通过退出 0
conda run -n py312 python skill/esg-skills/esg-monthly-report/scripts/validate_report.py \
  --file report.md --month 2026-11

# 招投标记录校验：有违规退出 1，通过退出 0
conda run -n py312 python skill/esg-skills/esg-bid-monitor/scripts/validate_records.py \
  --input records.json

# 每日推送窗口（Asia/Shanghai）
conda run -n py312 python skill/esg-skills/esg-bid-monitor/scripts/daily_window.py

# 月度调度：命中本月第 1 个工作日时输出上个月 YYYY-MM，否则退出 3
conda run -n py312 python skill/esg-skills/esg-monthly-report/scripts/run_monthly.py

# 金额分桶图：默认只统计中标金额；>=5 条有效金额输出柱状图+饼图，
# 1-4 条只输出柱状图，0 条删除同前缀旧图且不出图
conda run -n py312 python skill/esg-skills/esg-bid-monitor/scripts/chart.py \
  --input records.json --output-prefix esg_bid_dist --title "ESG 招投标金额分布"

# Markdown 转 PDF（可选）
conda run -n py312 python skill/esg-skills/esg-monthly-report/scripts/md_to_pdf.py \
  --input report.md --output report.pdf

# 测试
conda run -n py312 python -m unittest discover \
  -s skill/esg-skills/tests -p "test_*.py" -v
```

## 6. 定时触发

OpenCode 自身没有调度器，Skill 以手动触发为主。需要自动化时，用系统 cron 包一层 CLI，并显式固定时区和 `target_month`：

```cron
# 每个工作日 09:00 尝试；run_monthly.py 只在“本月第 1 个工作日”继续
# 把 <作业目录绝对路径> 替换成实际路径；节假日用 --holiday 追加
0 9 * * 1-5 cd <作业目录绝对路径> && TZ=Asia/Shanghai sh -c 'MONTH=$(conda run -n py312 python skill/esg-skills/esg-monthly-report/scripts/run_monthly.py) && opencode run "使用 @esg-monthly-report 生成 ${MONTH} 的中国神华 ESG 月报（target_month=${MONTH}）"' >> /tmp/esg-monthly.log 2>&1

# 每天 08:00（Asia/Shanghai）推送 ESG 招投标新增
0 8 * * * cd <作业目录绝对路径> && TZ=Asia/Shanghai opencode run "使用 @esg-bid-monitor 执行每日新增推送；窗口用 scripts/daily_window.py 计算" >> /tmp/esg-bid-daily.log 2>&1
```

`run_monthly.py` 默认按周一至周五判断工作日；中国法定节假日通过 `--holiday YYYY-MM-DD` 显式传入（可重复），节假日自动顺延到下一个工作日。不传 `--holiday` 时不会识别法定节假日，这是有意的简化。

macOS 用 launchd 的 `StartCalendarInterval` 可以达到同样的效果：把上面的 `sh -c` 命令写进一个 shell 脚本，再让 plist 每天 09:00 / 08:00 调用它即可。定时任务只负责发起调用，自然月和每日窗口分别由 `run_monthly.py`、`daily_window.py` 计算。

## 7. 已知限制与偏离

- **检索未实测**：本机没有 `DEEPSEEK_API_KEY`，`search_deepseek.py` 只验证了“缺密钥退出 2”和响应归一化的单元测试；真实接口的请求字段在 `build_payload()`、响应字段在 `normalize_results()`，若与预期不同只改这两处。
- **模型未固定**：作业建议 Qwen3.8-flash；当前环境不保证该模型可用，Skill 文档要求模型不可用时退回会话模型，但不降低引用与零幻觉要求。
- **PDF 是可选产物（对 README 的有意偏离）**：README 写“自动转换为 PDF 附件”，这里按“Markdown 为主、PDF 可选”实现，使用 reportlab 内置 `STSong-Light` 中文字体，不依赖 LaTeX、wkhtmltopdf 或 weasyprint。用户明确要求自动附件时，Skill 会在 Markdown 定稿后调用 `md_to_pdf.py`，失败只记录错误、不回滚 Markdown。
- **第 1 个工作日是近似实现（对 README 的有意偏离）**：`run_monthly.py` 默认按周一至周五计算，法定节假日需要显式传 `--holiday`，不会自动读取国务院放假安排。
- **历史汇总不写每日缓冲区**：`history` 只读 `daily_buffer.json` 做比对，避免两年历史数据灌进每日增量池；只有 `daily` 模式由 `daily_push` 一次性追加新记录。
- **自动化需要外部调度**：cron / launchd 示例只是包装命令，是否需要开机、补跑、失败重试由使用者自行配置。
- **数据规模**：DeepSeek 检索存在召回上限，历史汇总用半年度 × 关键词切片缓解，但无法保证覆盖全部标讯；报告需按实际样本量标注。
- **缓冲区是本地文件**：`daily_buffer.json` 没有加锁，不适合多进程并发写入。

## 9. 设计取舍

- **提示词分阶段，而不是真正隔离的子 Agent**：作业要求“多 Agent 协作”，但独立子 Agent 需要额外的本地配置和 ID 依赖。这里用 `agents/*.md` 拆成搜索、过滤、撰写、校验四个阶段，由 `SKILL.md` 顺序编排，结构可读、可复制，代价是上下文不隔离。
- **两个 Skill 各自复制共用脚本**：`search_deepseek.py`、`md_to_pdf.py` 在两边完全一致。用复制而不是共享目录，是为了满足“单个 Skill 目录拷走即可用”。
- **金额只接受万元正数或 `null`**：`chart.py` 不解析“约 1200 万”“1.2 亿”这类字符串，归一化由 `extract` 阶段完成；无法归一或为 `0` 的记录不进入图表，避免脚本层猜金额。
- **图表默认只统计中标金额**：`announcement_type="tender"` 的记录只进入文字和统计，不进入金额分桶；需要看预算分布时显式加 `--scope all`，避免把预算当成交金额。
- **每日缓冲区只有一个写入者**：`dedupe` 只读比对，`daily_push` 在每日流程末尾一次性追加，历史汇总不写 `daily_buffer.json`。
- **校验脚本只做机械检查**：`validate_report.py` 检查引用标记和日期范围，`validate_records.py` 检查字段、日期、金额类型和 URL 去重；语义正确性仍由 `validator` / `writer` 提示词约束。
