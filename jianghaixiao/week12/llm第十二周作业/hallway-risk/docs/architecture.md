# 楼道消防隐患识别 · 架构设计

## 1. 目标

输入一张图片（拍照或上传），输出结构化的消防安全风险评估。

## 2. 总体架构

```
┌──────────────────────────────────────┐
│ 浏览器（手机 / 电脑）                  │
│  · 摄像头拍照（st.camera_input）       │
│  · 上传图片（st.file_uploader）        │
│  · 风险卡片展示                        │
└──────────────────┬───────────────────┘
                   │ HTTP multipart/form-data
┌──────────────────▼───────────────────┐
│ 前端：Streamlit                        │
│  · 图片预览                            │
│  · 调用后端                            │
│  · 结果渲染（颜色/等级/证据/建议）      │
└──────────────────┬───────────────────┘
                   │ POST /v1/risk/analyze
┌──────────────────▼───────────────────┐
│ 后端：FastAPI                          │
│  · 文件校验（类型/大小）                │
│  · 图片压缩（Pillow）                   │
│  · 转 base64 data URL                  │
│  · 调用多模态模型                       │
│  · JSON 解析 + Pydantic 校验            │
└──────────────────┬───────────────────┘
                   │ OpenAI 兼容接口
┌──────────────────▼───────────────────┐
│ 多模态模型：Qwen-VL / DeepSeek-VL      │
└──────────────────────────────────────┘
```

## 3. 模块职责

| 模块 | 职责 | 不负责 |
|---|---|---|
| `frontend/app.py` | 拍照/上传、展示、调用后端 | 不接触模型、不持有 API Key |
| `backend/main.py` | HTTP 接口、参数校验、错误处理 | 不写提示词、不处理图片细节 |
| `backend/vision.py` | 图片压缩、base64、调模型、解析 JSON | 不处理 HTTP |
| `backend/prompts.py` | 提示词模板 | 不含业务代码 |
| `backend/schemas.py` | 请求/响应数据模型 | 不含逻辑 |
| `backend/config.py` | 模型名、基址、限制 | —— |

## 5. 两阶段判定（核心设计）

```
第一问：这张图是不是住宅楼道/楼梯间？
   ├─ 否 → risk_level = "非楼道"，结束
   └─ 是 → 第二问：风险等级 + 命中因素 + 依据 + 建议
```

**为什么拆两阶段**：

1. "非楼道"是一个特殊分支，和风险分级混在一起容易误判；
2. 两阶段更容易调试：第一问错了立刻能发现；
3. 以后可以把第一问换成 CLIP 预筛（更快更便宜）。

## 6. 接口契约

### 6.1 健康检查

```
GET /v1/health
→ {"status": "ok"}
```

### 6.2 风险评估

```
POST /v1/risk/analyze
Content-Type: multipart/form-data
字段：file（jpg/jpeg/png/webp，≤ 10MB）
```

成功响应：

```json
{
  "code": 200,
  "message": "ok",
  "data": {
    "is_corridor": true,
    "risk_level": "高",
    "risk_items": ["电动车", "飞线充电"],
    "reason": "楼道内停放电动车，并有从窗户垂下的充电线",
    "suggestion": "立即移走电动车，禁止飞线充电",
    "confidence": 0.92
  }
}
```

失败响应：

```json
{"code": 400, "message": "不支持的图片格式", "data": null}
{"code": 500, "message": "模型调用失败", "data": null}
```

## 7. 风险分级标准

| 等级 | 判据 |
|---|---|
| 高风险 | 电动车、电瓶、飞线充电等可能起火的元素 |
| 中风险 | 大量堆积物严重影响通行，或纸箱/木质家具等可燃物大量堆放 |
| 低风险 | 存在楼道堆物，但不严重 |
| 无风险 | 楼道干净，无堆放物 |
| 非楼道 | 与楼道无关的图片 |

> 安全原则：**宁可误报，不可漏报**。多个风险因素同时存在时取最高等级。

## 8. 关键实现点

| 点 | 做法 |
|---|---|
| 图片压缩 | Pillow，长边 ≤ 1280，JPEG quality 80 |
| base64 | `data:image/jpeg;base64,...` |
| 多模态消息 | `content` 数组：`image_url` + `text` |
| 结构化输出 | 提示词 + `response_format`（若支持）+ 正则兜底 |
| JSON 校验 | Pydantic `RiskAssessment` |
| 超时 | 30 秒；失败重试 1 次 |
| API Key | 只放后端 `config.py` / 环境变量 |

## 9. 测试与验收

| 类别 | 图片数 | 指标 |
|---|---|---|
| 高风险 | 5 | 召回率（最重要，不能漏报） |
| 中风险 | 5 | 准确率 |
| 低风险 | 5 | 准确率 |
| 无风险 | 5 | 准确率 |
| 非楼道 | 5 | 误判率 |

指标：

- 总体准确率
- 高风险召回率
- 非楼道误判率
- 平均响应时间
- JSON 解析成功率

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 手机摄像头无法打开 | 需要 HTTPS；先用上传兜底 |
| 图片过大超时 | 压缩到长边 1280 |
| 模型不返回 JSON | 提示词 + response_format + 正则兜底 |
| 高风险漏报 | 提示词明确判据 + 测试集统计召回率 |
| API Key 泄露 | 只在后端使用 |
| 非楼道误判 | 两阶段判定 |
