# 作业 2：Script 沉淀与“有 Script / 无 Script”对比

## 1. 对比设计

设置两组 Skill：

### A 组：无脚本 Skill

只提供 `SKILL.md`、报告模板和来源标准，由模型自主完成搜索、阅读、筛选、总结和写报告。

### B 组：有脚本 Skill

在相同 `SKILL.md` 基础上增加：

- 来源收集脚本
- 网页抓取脚本
- 去重脚本
- 证据账本脚本
- 引用校验脚本
- 指标统计脚本

两组使用相同模型、相同搜索工具、相同时间上限和相同报告模板。

## 2. 脚本分工

| 环节 | 无脚本 Skill | 有脚本 Skill |
|---|---|---|
| 搜索规划 | 模型自由生成 | 模板化检索矩阵 + 模型扩展 |
| 网页抓取 | 手动打开 | 自动抓取、缓存、重试 |
| 来源去重 | 依赖模型记忆 | URL 规范化和相似度去重 |
| 证据记录 | 临时整理 | JSONL 证据账本 |
| 引用检查 | 人工检查 | 自动检查引用编号和链接 |
| 报告生成 | 模型直接写 | 模板渲染 + 模型补充 |
| 运行记录 | 不完整 | 自动记录时间、来源数和失败率 |

## 3. 评价指标

### 报告质量

- 事实准确率
- 引用覆盖率
- 来源权威性
- 信息时效性
- 对矛盾证据的处理
- 分析深度
- 报告结构

### 过程效率

- 总耗时
- 抓取成功率
- 来源数量
- 重复来源比例
- 人工修正次数
- 多次运行结果稳定性

## 4. 示例对比结果

> 以下为作业示意数据，不是实际实验测量值。

| 指标 | 无脚本 Skill | 有脚本 Skill |
|---|---:|---:|
| 完成时间 | 约 45 分钟 | 约 25 分钟 |
| 可用来源数量 | 8—15 个 | 18—30 个 |
| 引用覆盖率 | 约 60% | 约 90% |
| 重复来源 | 较多 | 明显减少 |
| 抓取失败处理 | 不稳定 | 有记录和重试 |
| 报告格式一致性 | 中等 | 高 |
| 分析深度 | 依赖模型状态 | 中等偏稳定 |
| 多次运行波动 | 较大 | 较小 |

## 5. 结果分析

### 有脚本的优势

1. 减少重复劳动。抓取、去重、引用检查不需要每次重新完成。
2. 提高可追溯性。证据账本让每条结论都能回到原始来源。
3. 提高稳定性。不同次运行之间的结构和质量波动更小。
4. 方便统计和复盘。可以记录耗时、来源数量、失败率等指标。

### 有脚本的局限

1. 不能替代判断。来源是否可信、结论是否成立，仍然需要模型分析。
2. 可能降低探索性。如果检索模板过于固定，可能漏掉意外但有价值的信息。
3. 脚本维护有成本。网页结构变化、反爬策略和 API 限制都会影响脚本。

### 无脚本的优势

- 更灵活，适合开放式探索。
- 不需要维护代码。
- 对突发网页结构变化不敏感。

### 无脚本的局限

- 容易漏引用。
- 来源整理不稳定。
- 重复劳动多。
- 多次运行结果差异较大。

## 6. 最终结论

有脚本的 Skill 在结构化研究任务中优势明显，尤其是在来源收集、去重、引用检查和报告一致性方面。

无脚本的 Skill 更适合早期探索和开放式问题，但稳定性和可追溯性较弱。

最佳方案不是“全部脚本化”，而是：

> LLM 负责研究判断和综合写作，Script 负责确定性、重复性和可验证的工作。

## 7. 对照实验建议

如果后续需要真实实验，建议每个案例做 A/B 两组，每组至少运行 3 次，并保持模型、搜索工具、时间上限和输出模板一致。评分时采用盲评，并抽取关键事实逐条核对原始来源。
