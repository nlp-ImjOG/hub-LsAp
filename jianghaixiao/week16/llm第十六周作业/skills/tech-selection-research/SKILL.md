# 目标

针对给定的技术选型问题，自主搜索互联网资料，筛选可信来源，建立对比矩阵，并输出带引用和置信度的研究报告。

# 工作流程

1. 明确研究问题、使用场景、时间范围和评价指标。
2. 将问题拆成官方文档、GitHub 数据、Release Notes、Benchmark、社区评价和反面证据六类来源。
3. 只使用能够打开并核对的原始页面，不把搜索摘要当作证据。
4. 对每个候选方案记录：功能、成熟度、生态、学习成本、部署成本、风险和适用场景。
5. 建立“结论—证据—来源”对应表。
6. 输出对比矩阵、推荐结论、适用边界和风险说明。
7. 检查引用完整性、来源时效性和是否存在单一来源支撑的关键结论。

# 输出格式

- 一页结论摘要
- 研究范围与方法
- 候选方案对比表
- 关键发现
- 反面证据与争议
- 推荐方案与适用条件
- 风险与不确定性
- 来源列表

# 质量要求

- 关键结论至少有两个独立来源，或明确标注“单一来源”。
- 区分官方事实、厂商宣传和第三方评价。
- 数字必须能追溯到原始来源。
- 不伪造链接、日期、版本号或 Benchmark 数据。
- 结论必须说明适用场景，不输出脱离场景的“绝对最优”。

# 脚本

- `scripts/collect_sources.py`：整理搜索候选结果。
- `scripts/build_evidence_ledger.py`：生成证据账本。
- `scripts/validate_report.py`：检查引用和报告结构。
