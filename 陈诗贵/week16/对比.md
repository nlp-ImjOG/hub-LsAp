# 不使用 Skill / 普通 Skill / 带确定性脚本 Skill 效果对比

> 对应第 16 周作业：
> 案例一「ESG 月报 SKILL/AGENT」、案例二「ESG 投标信息汇总 SKILL/AGENT」。
> 所有 skill 均要求自主联网检索、自主筛选信息、形成报告；脚本版把可确定的环节固化为代码，LLM 只做抽取与总结。

## 一、交付物

**接入方式说明**：DeepSeek 官方 API 不提供联网检索能力，因此联网环节由脚本调用搜索引擎（360 优先，Bing / DuckDuckGo 降级）完成，内容抽取与总结由 `LLM_BASE_URL` / `LLM_MODEL`（当前为 `deepseek-flash`）完成。纯提示词版则由运行它的 Agent（Claude Code / DeepSeek Agent）使用其可用的联网工具完成检索。

## 二、三种方式总对比

| 维度 | 不使用 Skill | 普通（纯提示词）Skill | 带确定性脚本 Skill |
|---|---|---|---|
| 触发方式 | 每次手动描述需求，描述不同结果就不同 | `description` 命中自动加载，输入格式固定 | 自动加载 + 固定命令序列 |
| 检索范围 | 依赖模型临场发挥，检索词每次变化 | 提示词给出检索方向，仍由模型临场决定 | 检索词由代码生成（月报 11 条 / 投标 12 条），可版本管理 |
| 信息筛选 | 模型自行判断，标准不稳定 | 给出了筛选标准，但执行靠模型自觉 | 时间窗口、去重、分类白名单由代码强制执行 |
| 数值计算 | 模型口算，金额"万/亿"换算常错 | 规则写在提示词里，仍由模型计算 | `parse_amount()` 等纯函数计算，样例已单测通过 |
| 事实校验 | 无 | 提示"不得编造"，无强制手段 | 金额/日期必须逐字出现在原文，否则置空并告警 |
| 输出格式 | 每次结构不同 | 模板固定，但细节可能遗漏 | Markdown 模板 + 质量检查表，附录与正文数量强制一致 |
| 可复现性 | 低 | 中低 | 高（统计部分完全相同；抽取部分 temperature=0 + 证据校验） |
| 幻觉风险 | 高 | 中 | 低（无原文依据的数字进不了报告） |
| 耗时 / Token | 最低 | 中 | 最高（搜索 + 抓正文 + 多次 LLM 调用） |
| 维护方式 | 改对话 | 改 SKILL.md | 改 SKILL.md + 查询词/规则/模板，可写单测 |

一句话结论：**普通 skill 解决"流程不固定"，脚本 skill 解决"结果不可信、不可复现"。** 代价是更高的耗时与工程成本。

## 三、案例一：ESG 月报

需求：汇总过去一个月的 ESG 政策/评级/标准动态、行业新闻与最佳实践、客户公司动态及对标企业关键行动，以中国神华为示例。

| 环节 | 不使用 Skill | 普通 Skill | 带脚本 Skill |
|---|---|---|---|
| 报告周期 | 模型自行理解"过去一个月"，可能用上月或近 30 天 | 提示词明确"滚动 30 天 / 上一自然月" | `--as-of` + `--days` 由代码计算窗口，窗口外条目单独存放 |
| 政策 / 行业 / 公司 / 对标 | 章节常缺失或内容偏题 | 四段式模板 + E/S/G 标签 | 分类白名单校验，非法分类归并并告警；四段必有独立章节 |
| 来源可追溯 | 常出现无来源表述 | 要求标注来源 | 每条必须带 URL + 域名，附录自动生成信息清单 |
| 日期准确性 | 容易把旧闻当本月新闻 | 提示优先本月 | 日期必须能在原文找到（多种中文写法），否则进入"日期未知"清单 |
| 重复信息 | 同一事件多次出现 | 提示去重 | URL + 标题规范化去重，重复项单独记录 |
| 摘要与建议 | 直接生成，可能与正文脱节 | 要求与正文对应 | LLM 只能引用已确认条目编号，脚本校验引用编号是否存在 |
| 质量检查 | 无 | 提示词末尾有自查清单 | 7 项检查自动执行并打印 `[✓]/[✗]` |

## 四、案例二：ESG 投标信息汇总

需求：汇总过去 2 年 ESG/可持续/双碳相关中标情况，分析热点方向与中标金额分布；并每天推送新招标。

| 环节 | 不使用 Skill | 普通 Skill | 带脚本 Skill |
|---|---|---|---|
| 金额换算 | 口算，`1.2亿元`、`3500万元`、`2,460,000元` 混算易错 | 提示词列出换算规则 | 纯函数换算，已用 9 组样例验证通过（含全角、逗号、无单位告警） |
| 统计口径 | 每次不同，区间边界不固定 | 提示词定义五档区间 | 代码固定五档（左闭右开），项目数之和可核对 |
| 中位数 / 均值 | 模型估算 | 提示计算方式 | `statistics.median` 精确计算，未披露金额不计入 |
| 两年窗口 | 易把 2023 年项目算进来 | 提示"过去 24 个月" | 按自然月精确减 24 个月，窗口外记录单独列出 |
| 重复公告 | 同项目多次公告重复计数 | 提示去重规则 | (日期, 项目名称, 采购人) 去重，保留首条 |
| 每日推送 | 容易把历史信息混入 | 提示只取当日 | 只保留公告日期等于当天的记录；无新增时明确输出"当日无新增" |
| 关注度判断 | 主观随意 | 提示分级标准 | 金额阈值 + 关键词规则确定性执行并给出理由 |

## 五、确定性边界：哪些交给脚本，哪些留给 LLM

| 交给脚本（确定性） | 留给 DeepSeek（智能） |
|---|---|
| 检索词生成、搜索调用、正文抓取 | 从素材中抽取标题、日期、金额、采购人等字段 |
| 时间窗口过滤、URL/标题去重 | 撰写 1~2 句事实摘要与影响判断 |
| 金额单位换算、区间与分位数统计 | 生成月报摘要、ESG 建议、信息缺口说明 |
| 分类/维度白名单校验、字段证据校验 | 判断素材与 ESG 的相关性（再由脚本过滤） |
| Markdown 模板渲染、附录生成 | — |
| 质量检查、告警输出 | — |

这样分工的好处：LLM 只做它擅长且可核对的事（读文本、写摘要），凡是"算得出来、比得了、必须一致"的事情都由代码完成。

## 七、本仓库已验证项与局限

已验证：

- DeepSeek 接口连通（`LLM_BASE_URL=https://api.deepseek.com/v1`，模型 `deepseek-flash`）。
- 真实联网搜索可用（360 检索返回相关结果并解析出真实 URL；Bing 中文结果质量较差，作为降级源；Google News 在当前网络不可达）。
- 金额换算 9 组样例全部正确：`1.2亿元→120000000`、`3500万元→35000000`、`980万→9800000`、`2,460,000元→2460000`、`12.5 亿→1250000000` 等。
- 统计与日报规则用临时用例验证：24 个月窗口过滤、重复去除、金额区间、中位数、关注度分级均符合预期。
- 所有脚本 `py_compile` 通过。

局限（如实说明）：

1. **搜索引擎召回限制**：公开搜索结果中真正属于"过去一个月"、且与客户强相关的新闻数量有限，脚本不会用旧闻或编造内容补足；条目少时报告会如实变短。
2. **LLM 抽取仍有随机性**：脚本用"金额/日期必须出现在原文"做硬校验，但摘要措辞每次可能略有不同，因此只有统计与格式部分达到完全可复现。
3. **未内置任何示例数据**：所有报告内容必须来自本次实时检索；搜索失败或无 Key 时脚本直接报错退出，不会产出伪造报告。
4. **成本**：脚本版每次运行包含多次搜索、网页抓取与 LLM 调用，耗时与费用都高于纯提示词方式，适合有固定节奏（月报、日报）的场景。

## 八、结论

- **一次性、低风险、追求速度** → 不使用 skill。
- **需要固定工作流、但数据量不大、人工会复核** → 普通提示词 skill。
- **周期性、需要金额数值准确、结果可审计可复现**（ESG 月报、招投标情报） → 带确定性脚本的 skill，LLM 只负责"读懂并总结"，不负责"计算与把关"。
