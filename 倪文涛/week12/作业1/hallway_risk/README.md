# 楼道消防安全风险识别 Demo

使用手机拍照或上传单张图片，通过硅基流动云端的 **Qwen3-VL-32B-Instruct** 分析楼道场景，展示分类结果和判断依据，用于课程作业演示。

> 当前阶段：前后端代码已实现，并完成隔离云端传输的接口检查。填写有效密钥和模型标识后可启动真实识别。尚未完成真实云模型的五类图片验收及实际手机拍照验证，不承诺识别准确率。

## 1. 项目目标与范围

- 后端使用 Python FastAPI，前端使用原生 HTML、CSS、JavaScript。
- FastAPI 同时提供静态页面和识别接口，前后端同源访问，无需单独启动前端服务。
- 服务运行在电脑上，支持电脑本机和同一 Wi-Fi 下的手机访问；电脑需要能够访问硅基流动。
- 手机通过系统相机拍照，或从相册选择图片；电脑支持本地文件上传。
- 每次由用户主动提交一张图片，完成一次分析；不做连续视频检测。
- 结果区域只展示一个分类和对应的判断依据，不展示处理建议、风险框或风险位置。
- 应用不持久保存照片、分析结果或历史记录；刷新页面后清空当前图片和结果。

首版不包含登录、用户管理、数据库、物业处理流程、批量识别、HEIC 支持、本地模型推理或 Streamlit。

## 2. 分类规则

本项目采用作业定义的五种分类，不新增第六种分类。

| 分类 | 判定规则 |
| --- | --- |
| 高风险 | 楼道内出现电动车、电瓶、明确的飞线充电等可能起火的元素。 |
| 中风险 | 楼道内有大量堆积物严重影响通行，或堆放大量纸箱、木质家具等可能造成火势蔓延的堵塞物。 |
| 低风险 | 楼道存在堆物，但数量或对通行的影响不严重。 |
| 无风险 | 楼道干净，无堆放物品。 |
| 非楼道 | 图片内容明确与楼道场景无关。 |

判定顺序与约束：

1. 先确认照片是否属于楼道场景；明确无关的场景返回“非楼道”。无关场景中即使出现电动车，也不直接套用楼道高风险规则。
2. 对楼道场景，按 **高风险 > 中风险 > 低风险 > 无风险** 返回唯一分类。多个条件同时出现时选择最高等级。
3. 只根据照片中的可见内容判断，不推测封闭柜体或遮挡区域中有危险物品，不凭空认定正在充电。
4. 判断依据应简短、具体，说明可见现象及其与分类的关系；不能确认材质或充电状态时，不把推测写成事实。
5. “大量”“严重影响通行”采用模型对可见场景的定性判断，首版不引入物品数量或通道宽度的测量算法。
6. 全黑、严重模糊或遮挡到无法判定的照片按分析失败处理，不强行归入“无风险”或“非楼道”。模型仍可能误判，需通过代表图片检查实际效果。

## 3. 页面与交互

页面依次包含：项目标题、图片输入入口、当前图片预览、分析按钮、加载或失败状态、分类与判断依据。

### 图片输入

- 提供独立的“拍照”和“上传图片”入口，每次仅选择一张图片。
- 拍照使用原生文件输入的 `capture="environment"` 能力，请求调用手机系统相机并优先使用后置摄像头，不使用网页内实时取景。
- 上传入口不设置拍摄限制，允许从相册或本地文件中选择图片。
- 支持 JPEG（`.jpg`、`.jpeg`）、PNG、WebP；不支持 HEIC。
- 单张文件上限为 10 MB，统一按 `10 × 1024 × 1024` 字节校验，前后端保持一致。为避免解码占用过多内存，图片另限制为不超过 4000 万像素。
- 前端提供格式和大小提示；后端同时验证文件大小、真实图片格式和能否正常解码，不仅依赖扩展名或浏览器声明的 MIME 类型。

系统相机是否直接打开、是否可选择镜头，受手机系统和浏览器影响；电脑上拍照入口可能表现为普通文件选择器。实际演示手机必须单独验证。如拍照入口不可用，可以先通过系统相机拍照，再从上传入口选择照片。若手机输出 HEIC，需要先转为受支持格式。浏览器行为参考 [MDN capture 文档](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/capture)。

### 分析流程

1. 用户拍照或选择图片，页面显示预览；提交前可重新拍摄或替换。
2. 用户点击“开始分析”，前端将图片上传到后端。
3. 等待时展示加载提示，禁用重复提交；首版分析期间也禁用图片替换，避免结果与预览错配。
4. 成功后展示唯一分类与判断依据，保留当前图片预览。
5. 失败时展示“分析失败，请重新拍摄或重试”，恢复操作，不展示本次风险等级。
6. 选择新图片或开始新一轮分析时，清除上一轮结果；刷新页面后清空当前状态。

格式不支持、文件超限等输入问题，应在提交前尽可能给出明确原因。模型超时、鉴权失败、限流、服务异常、返回无效内容等情况统一进入失败状态；页面不展示密钥或上游原始异常。

## 4. 技术方案

```text
电脑浏览器 / 同一 Wi-Fi 下的手机浏览器
                    |
       页面访问 / 单张图片上传
                    |
        FastAPI（页面与识别接口）
                    |
          图片校验、图文消息构造
                    |
         OpenAI Python SDK
                    |
       硅基流动 Chat Completions
          Qwen3-VL-32B-Instruct
                    |
       分类与依据校验 → 返回页面
```

云端调用约定：

- 使用 OpenAI Python SDK 的 Chat Completions 接口，不使用本地 Transformers/CUDA 推理。
- 国内服务的 `base_url` 为 `https://api.siliconflow.cn/v1`，依据 [硅基流动快速上手文档](https://docs.siliconflow.cn/docs/userguide/quickstart)。
- 目标模型为 Qwen3-VL-32B-Instruct，官方 [模型中心](https://www.siliconflow.cn/models) 列有该模型。具体 API 模型标识以控制台或模型列表接口为准，实施时核对后通过环境变量配置；当前尚未使用真实账号验证模型权限和调用结果。
- 后端将图片构造成 Base64 Data URL，通过 `image_url` 与分类提示词一起发送，不需要为上传图片提供公网地址。图文消息格式参考 [视觉语言模型文档](https://docs.siliconflow.cn/docs/userguide/capabilities/vision)。
- 使用非流式请求，待完整结果返回并验证后再展示。
- 提示词要求返回可解析的分类与依据；后端将“中等风险”“无隐患”分别统一为“中风险”“无风险”，只保留分类与依据两个字段，并检查分类是否属于五种允许值、依据是否为非空文本；模型明确返回失败时仍拒绝作为正常分类。
- 质量不足可通过内部失败标记表达，由后端转换为失败响应，不向用户增加第六种分类。不能只凭 JSON 格式合法就认定图片清晰或结论正确。
- 不依赖未经验证的供应商 JSON Schema 支持，也不将无法解析的模型原文直接作为有效分类展示。
- 模型请求默认总超时为 300 秒（5 分钟），SDK 网络超时也设为该值；可通过环境变量调整（大于 0、不超过 300 秒）。SDK 自动重试已关闭，由用户手动重试。前端调用后端接口的总超时为 300 秒，包含上传和等待分析的时间。

图片解码后校正 EXIF 拍摄方向，长边超过 2048 像素时等比例缩小，以质量 90 转为 JPEG 后发送，不携带原图 EXIF。透明图片使用白色背景，动画图片只分析首帧。细节保留效果需结合真实图片验收，不承诺推理速度。

## 6. 接口

### 页面与静态资源

- `GET /`：返回首页。
- `/static/`：提供 CSS、JavaScript 等静态资源。

### 单张识别

- 路径：`POST /api/analyze`
- 请求类型：`multipart/form-data`
- 字段：`file`，单张图片文件。

成功响应示例（仅用于说明协议，并非真实识别结果）：

```json
{
  "risk_level": "高风险",
  "reason": "楼道内可见一辆电动车，符合高风险判定条件。"
}
```

`risk_level` 只允许“高风险”“中风险”“低风险”“无风险”“非楼道”；“非楼道”是场景分类，不参与风险等级排序。

分析失败响应示例：

```json
{
  "error": {
    "code": "ANALYSIS_FAILED",
    "message": "分析失败，请重新拍摄或重试"
  }
}
```

失败响应不携带 `risk_level` 或 `reason`。错误状态如下，前端均需结束加载并恢复操作：

| HTTP 状态 | 场景 | 页面行为 |
| --- | --- | --- |
| 400 / 422 | 缺少图片、文件损坏或请求不合法 | 提示检查或重新选择图片。 |
| 413 | 图片超过 10 MB | 明确提示大小限制。 |
| 415 | 不支持的真实图片格式 | 明确提示仅支持 JPEG、PNG、WebP。 |
| 502 | 上游调用失败、模型输出无效或图像无法判定 | 提示“分析失败，请重新拍摄或重试”。 |
| 504 | 上游模型调用超时 | 提示“分析失败，请重新拍摄或重试”。 |

未配置必要参数时，服务在启动阶段给出明确的本地配置错误。应用日志记录图片格式与尺寸、转换前后字节数、模型返回长度、字段类型、分类、状态、耗时和错误类型，不记录密钥、图片正文、完整判断依据或完整模型响应；不应开启 SDK 的请求体调试日志。

## 8. 启动方式

首次启动前准备好硅基流动 API 密钥、可用模型权限及网络连接。

在项目根目录激活已有 Conda 环境、确认解释器版本，再安装依赖：

```bash
conda activate badou_env3.12
python --version
python -m pip install -r requirements.txt
cp .env.example .env
```

在本地 `.env` 填写有效的硅基流动密钥及完整模型标识后，启动同一个前后端服务：

```bash
python -m uvicorn app.api:app --host 0.0.0.0 --port 8000
```

也可在项目根目录执行 `python main.py`，或在 PyCharm 中选择 `badou_env3.12` 解释器运行根目录的 `main.py`。复制 `.env.example` 仅需首次执行，已有 `.env` 时不要覆盖。

运行自动检查：

```bash
python -m unittest discover -s tests -v
```

- 电脑本机访问：`http://localhost:8000`。
- 手机访问：`http://<电脑局域网IP>:8000`；手机和电脑处于同一 Wi-Fi，电脑允许局域网访问该端口。
- `0.0.0.0` 是监听地址，不是供手机打开的目标地址；手机上的 `localhost` 指手机自身。
- 首版以局域网 HTTP 和系统相机文件输入为演示方案；实际拍照兼容性以目标手机测试为准，不提供网页内摄像头视频流，也不部署公网服务。

## 9. 数据处理与会话约定

- 当前图片和结果仅维护在当前页面内存中，不写入 Local Storage、IndexedDB 或历史记录。
- 后端在请求期间临时处理图片，不建立持久图片或结果存储；若上传框架使用临时文件，应在请求结束或失败后关闭并清理。
- 分析接口响应不应被浏览器缓存；刷新后不恢复上次结果，也不自动重复发送上次请求。
- 图片会经后端发送至硅基流动。应用不保存历史，并不意味着云服务商不留存数据；服务商侧处理规则以其政策为准，不在本项目中作删除承诺。
- 手机系统相机是否另外将照片保存到相册，由手机系统决定，属于应用之外的行为。

## 10. 验收计划

验收目标为“流程跑通 + 五类代表图片验证”，不设未经测量的准确率或固定响应秒数门槛。

### 代表图片验证

覆盖五种分类，建议每类至少 2 张、合计至少 10 张；为每张图片事先给出人工预期分类及依据，并在 `tests/acceptance.md` 记录实际结果、是否一致和实测耗时。样本由后续验收阶段准备，本阶段未提供图片或结果。

重点覆盖：

- 高风险：电动车、电瓶或明确飞线充电；兼有纸箱时仍应优先判高风险。
- 中风险：大量纸箱、木质家具或严重影响通行的堆积物。
- 低风险：少量、影响不严重的楼道堆物。
- 无风险：干净、无堆放物品的楼道。
- 非楼道：明确无关的场景，包括楼道之外出现电动车的图片，检查场景判定是否正确。

### 功能与异常检查

- 电脑可打开页面并上传图片，手机同一 Wi-Fi 下可访问并验证系统拍照、相册上传。
- JPEG、PNG、WebP 均可预览和提交；HEIC、伪装扩展名、损坏文件被正确拒绝。
- 大小边界校验一致：不超过上限的有效文件可提交，超过上限被拒绝。
- 可替换未提交图片；等待期间有加载提示，不能重复提交或替换当前图片。
- 正式识别调用真实云模型，页面展示五类之一及非空、与可见内容相关的依据。
- 严重模糊或全黑图片不被当作无风险；无法判定时进入失败状态。
- 超时、鉴权失败、限流、无效模型输出等错误不会导致页面卡在加载状态，也不会展示上一轮的风险等级。
- 替换图片、开始新分析及刷新时正确清除旧结果；刷新不自动触发收费调用。
- 应用无持久照片、结果或历史记录；前端及日志中不泄露密钥。

接口自动检查可隔离云端调用，验证成功响应、输入限制和异常分支；这类检查不能替代使用真实模型的五类图片验收。硬件环境、服务可用性和图片内容均可能影响实测结果，应如实记录偏差。

尚需配置真实密钥后验证账号模型权限、五类代表图片的真实识别效果，以及目标手机系统相机与局域网访问行为。人工验收表见 `tests/acceptance.md`。

## 12. 识别失败排查

重启后端后重试，从终端复制同一次请求的 `image_received`、`image_prepared`、`model_response`、`model_json`、`model_validation` 和 `analysis status` 日志。图片格式不支持会在模型调用前失败；`ValidationError` 表示结果字段未满足约定，需要看字段与错误类型进一步定位。`favicon.ico` 的 404 与识别接口无关，页面已设置空图标以避免该请求。
