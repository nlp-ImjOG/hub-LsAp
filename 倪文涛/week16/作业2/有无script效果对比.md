## 3 内容质量与可读性

### 3.1 核心判断两版都较谨慎

两版都只把综合ESG治理与报告服务计为有效最终中标，都不把168万元和149万元候选报价当作最终成交价，也不把两份报价视为两笔交易。两版均拒绝在1包且金额缺失的基础上推导市场规模、增长率、季节性、市场份额或供应商胜率。

这些是报告可靠性的关键，但并非B版新增的能力。A版已经完整做到，说明明确的技能规则与模型复核本身就可以产生较严谨的结果。script 的价值主要在于把部分规则固定执行、便于再次计算；本次不能据最终结论认定B版准确率更高。

### 3.2 A版适合连贯阅读

A版按“摘要—样本与方法—采购需求与典型项目—统计分布—供应商与行动—待核验与排除—复核”展开。读者先了解项目，再看统计和建议，理解路径较连贯。

A版的五项行动表把依据、下一步和边界放在一起，分别覆盖综合治理、气候量化、评级与供应链、神东碳盘查和结果补核。B版主要建议压缩为三条，部分补核动作散落在后文。对需要直接安排后续工作的读者，A版更方便。

A版还单列两个排除案例：窗口外的零碳矿井标准体系研究，以及缺少明确双碳交付要求的柳塔生态基地工程。它们能具体说明“为什么看起来相关却不能纳入”，B版的一般性排除规则没有完全保留这种解释力。

### 3.3 B版字段更统一但存在拼接感

B版以“观察—业务含义—限制”组织摘要，增加统一的成交明细表和观察维度表，便于横向查阅采购人、供应商、日期、金额和来源。其对R002二次挂网线索、R003历史合同资格要求等描述也更细。

但B版在“局限与待核验事项”之后，又接上“典型项目与事件链”“待核验线索附录”等章节，结束性内容出现在主体分析之前。配套 `appendix.md` 与最终报告末尾逐字一致，支持其正文存在模板主体加补充附录的组合形式。最终交付仍需要统一调整顺序和重复内容。

B版多处自动附上R001最终结果链接，而相邻论述实际依赖候选业绩表或招标资格要求。正文通常也提供了对应链接，所以不宜直接判为无依据；但反复出现同一个R001引用增加了阅读负担，也说明“引用ID存在”不等于“当前链接足以支撑这句话”。

## 4 线索覆盖的变化

B版线索从7条变为10条，并不是简单在A版后面追加3条。按项目内容对照，而非沿用已经变化的L编号，可以分为以下三类。

| B版增加5项 | 神山露天煤矿碳盘查、湖南公司社会责任报告、向低碳院采购技术服务、广东环保管家、铁路绿色新材料研发 | 拓宽了待筛查主题及采购主体 |

B版新增项目中，部分仍存在相关性、最终状态或采购时点归属不明的问题。例如1780万元“低碳院技术服务”不能因为机构名称含“低碳”就列入双碳采购金额。B版对此保留了限制，避免把线索数量扩大误写成成交成果扩大。

因此，可以说B版的线索范围有所变化和拓宽，但不能说检索更全面、召回率更高，或新增线索由 script 直接带来。两版均未形成完整的历史原文覆盖。

## 5 script 带来的可核查改进与实际限制

### 5.1 固定了数据处理流程

对照两版技能可见，`references/search.md`、`references/history.md`、`references/data.md`内容一致；主要改动是在技能主文件中接入脚本化工作流，并把统计和报告生成指定为固定脚本。原有无 script 版也已经要求建立结构化明细、保存统计依据，并允许使用计算或表格工具。“无 script”指没有随技能打包的专用脚本，不能理解为全程不能计算或不能使用工具。

根据B版的 [脚本化工作流说明](/Users/chenmei/Documents/个人文件夹/八斗AI/hub-LsAp/倪文涛/week16/作业2/esg_bidding_summary/references/scripts.md)，其分工如下。这里描述的是文档规定的能力，不等于本次运行验证了全部功能。

| 组件 | 规定承担的工作 | 仍需要模型或人工完成的工作 |
| --- | --- | --- |
| collect.py | 生成检索计划、可选搜索接口、URL整理和正文采集 | 执行可用搜索、识别正文、判断相关性与公告阶段 |
| summarize.py | 输入校验、金额计算、分类分布、事实卡整理 | 核验原文并准确填写记录 |
| render_report.py | 重算统计、套模板、检查引用及转义 | 写分析建议、检查引文是否支撑结论、调整最终阅读顺序 |

B版更容易在已核验数据发生变化后重新计算和排版。但“可重复计算同一份输入”与“可重复获得相同的联网研究结果”是两件事，后者仍受网站状态、检索结果和判断过程影响。

### 5.2 配套文件确实支持报告的关键数字

本次直接核对B版运行目录，得到以下结果。

| 文件 | 核对结果 | 对交付的价值 |
| --- | --- | --- |
| records.json | 3项记录；R001为primary／awarded，R002和R003为secondary／unknown；最终金额均为空 | 能追查纳入状态，并保留候选价与最终金额的区别 |
| summary.json | 纳入1包；核心金额样本0；总额、均值和分位数为null；R002、R003被排除 | 与正文核心统计一致 |
| events.jsonl | 5条事件记录 | 可以区分同一项目不同阶段 |
| leads.json | 10条线索 | 可以继续补核，不必从正文重新抄录 |
| search-log.jsonl | 62条查询记录 | 支持报告中的实际查询条数说明 |
| plan.json | 144条计划查询 | 计划与执行分开；不能直接以62÷144作为计划完成率 |
| sources/sources.json | 3条采集记录全部为error，错误为URLError | 抓取失败得到明确留存 |
| file-integrity.json | 留存原有内容文件保全检查说明 | 有助于追踪文件变动，不证明采购事实正确 |

这些材料降低了复查和后续加工的成本，是本次B版最有证据支持的优势。其价值是“记录可检查”，不能把日志本身当作对所有查询及判断的独立认证。

### 5.3 本次没有体现自动采集和金额分析的增益

B版对三个重点官方网页的脚本采集全部失败。正文及项目证据描述表明，关键核验仍通过浏览器完成。脚本留下失败原因有利于排查，但本次没有证据表明它提高了正文抓取成功率，也没有解决国家能源e购历史结果访问缺口。

两版的可比最终金额都是0条，因此脚本即使具备均值、分位数和金额分档能力，也未在本次形成更丰富的价格分析。它对缺失值处理的规范化有价值，但不能填补原公告没有披露的金额。

此外，B版统计JSON的空金额档求和为0，而总体金额为null。正文已专门解释空档的0不表示观察到零元成交，说明面向读者的语义检查仍不能完全交给数字输出。

## 6 综合评价与改进建议

| 评价维度 | 本次判断 | 主要依据 |
| --- | --- | --- |
| 核心研究结论 | 基本持平 | 有效成交、金额缺口和关键限制相同 |
| 成交事实与金额准确率 | 无法证明B更高 | 没有独立金标准，两版关键口径一致 |
| 正文完整性与连贯性 | A略优 | 行动表、逐项排除案例及章节顺序更完整 |
| 字段统一与统计检查 | B更有基础 | 固定记录、统计JSON和模板存在 |
| 过程追溯与继续更新 | B明显更方便 | 查询、事件、线索、访问结果分别留存 |
| 检索覆盖与自动采集 | 没有确认提升 | 有效样本未增加，3条脚本采集均失败 |
| 耗时、Token和成本 | 本次无法比较 | 没有可比的运行计量数据 |

建议采用“结构化数据和固定脚本＋模型核验与编辑”的方式继续完善，并优先做以下四项改进。

1. **统一最终报告顺序。** 采用“摘要—口径与覆盖—典型项目—统计—行动建议—待核验与排除—交付说明”，把局限归并到方法或末尾，避免模板完成后直接追加主体章节。
2. **保留可追踪的增删说明。** 延续A版的具体排除案例；线索更新时标明新增、保留、合并及移除原因，避免B版替换了部分线索却没有交代去向。
3. **让引用对应具体证据。** 招标资格引用招标公告，候选报价引用候选公示，中标事实引用最终结果；对跨项目线索单独留证据，减少机械重复附加R001链接。
4. **以相同输入检验脚本收益。** 固定公告集、查询预算和评价口径，对照遗漏、重复计数、金额错误、修改后重算耗时以及最终阅读质量，再判断脚本节省了多少成本。当前1包且金额缺失的样本不足以展示复杂统计的优势。

对这两份成品最稳妥的评价是：**有 script 版提升了交付过程的可检查性和后续复用条件；无 script 版已具备相近的研究判断质量，并在一次性报告的组织表达上保留优势。** 下一步应把二者的长处合并，而不是用“有脚本”直接代替质量评价。
