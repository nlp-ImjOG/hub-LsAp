# 每日增量监控与定时推送

## 本次任务边界

“扫描今天”“生成日报”执行一次；“每天推送/启动持续监控”才配置调度。用户说“仅构建技能、暂不启用”时，交付技能即可，不能偷偷创建暂停/活动任务或向外发消息。明确的后续启动指令可改变该偏好。

默认持续任务为中国大陆、北京时间每天09:00、当前 Codex 聊天；用户已指定的时间、范围和渠道优先。邮件、企业微信、钉钉、飞书等外部渠道仅在用户指定且有相应工具/授权时使用；不可假装有这些能力，也不为其自动注册账号。

## 状态与增量规则

在用户项目固定目录 `esg-bidding-state/` 保留以下小文件，不用临时会话记忆替代持久状态：

- `config.json`：schema_version、timezone、范围/排除、关键词/来源列表、用户画像、状态目录、推送渠道、任务ID（实际创建后才填）。
- `records.json`：已核验项目包件当前快照；字段遵守 data.md。
- `events.jsonl`：首次发现、变更前后值、原文、证据、发现时间、首次发布时间、事件ID。
- `checkpoint.json`：各来源/主题最后成功覆盖的区间终点、上次尝试、失败原因、待补范围。只有成功访问和筛选完成的来源可推进。
- `deliveries.jsonl`：报告路径、包含的事件ID、生成时间、平台返回的消息/任务凭据与投递状态。无确认时不能把“已生成”标成“已送达”。

每次运行：

1. 读取配置、状态、未完成运行和上次报告；首次使用初始化空状态，不复用不存在的历史数据。
2. 首次默认回看7天，另搜更早发布但仍可报名的项目，标为“初始在招存量”。后续对每个来源从其成功检查点向前重叠至少3天到当前时点；停机超过3天时覆盖整个空档加重叠，不只搜最近3天。每周补扫近30天，捕获延迟收录；记录覆盖范围。
3. 搜索并读正文，合并同项目/包件/轮次的事件。跟踪尚未截止项目时回查最新更正/终止；新URL、转载日期或页面浏览量变化不算新商机。
4. 用 `record_id + 事件类别 + 规范化实质字段` 生成稳定事件指纹（例如排序键JSON的SHA-256）；实质字段包括阶段、原始公告日期、预算/限价、服务范围、资格条件、报名/文件/投标截止、暂停或取消信息。不要把抓取时刻、排序、访问量和跟踪参数放入指纹。事件内容确实变化才再推送；更正恢复旧值仍以新的正式公告事件标识区分。
5. 判断可行动性：资格预审/报名/文件获取截止可能早于投标截止。对尚未报名者，以必须完成的最早截止为准；已过报名期但仍在投标期的标为“仅已报名者可继续/报名资格待核验”，不能写“可立即报名”。截止未知单列待核验，只有日期则保留日期精度。
6. 区分：新发布、迟发现补录、初始存量、实质变更、储备意向、即将截止、失效。当天发现的旧项目不能写成“今日发布”；已终止/已截止移出可报名清单，但有变化时提醒已跟踪用户。
7. 先完整落盘本次候选更新、报告与事件，再原子替换有效状态（同目录临时文件后 rename/replace，保留上次有效文件）。出现并发运行则由后启动运行退出并报告已有运行，不互相覆盖；可用原子创建的运行锁，异常遗留锁先核实运行已停止后处理。
8. 发布当前日报或使用已授权渠道，保留平台返回凭据。仅有报告文件表示 generated；工具确认提交可标 submitted，明确送达回执才标 delivered。当前最终回复无法先取得送达回执时保持待确认，不伪造成功；后续先检查上一报告与可用运行结果。重试复用事件ID和报告ID，避免重发已确认送达项；平台无确认能力时声明可能重复，优先不漏实质事件。
9. 部分来源失败时发布已核验新增，并附未覆盖来源和补查区间；不推进失败来源检查点。全部来源失败时报告“本次监控未完成”，不能说“无新增”。

不要为每个失败无止境重试：单源原文失败后尝试一个合理替代来源，仍失败则入补查队列。下一运行再查；无法覆盖的长期来源在周检中明确提示调整。

## 机会排序与日报

不凭空打胜率分。优先级按可解释规则：

- P1：直接相关且能采取行动，最近必需截止在72小时内，或已跟踪项目有重要变更。
- P2：直接相关、仍开放且信息较完整；预算大小只作排序辅因，不等于适合用户。
- P3：采购意向、较弱相关延伸项目或关键时间/资格待核验。

未有用户企业资料时写“资质匹配待核验”。不要省略小金额但高度相关项目。日报主文选最值得行动的项目；其余完整明细另附，说明主文是否截断。

日报默认包含：

1. 检索时点与覆盖区间，新增、补录、变更、储备、临期各有多少；类别可能重叠则说明，独立项目数去重。
2. 优先项目表：优先级/推荐理由、名称/包件、采购人、地区、主题、预算/最高限价（明确不是成交额）、公告发布日期、报名/文件获取截止、投标截止、当前状态、原文。
3. 每项关键门槛、交付物、报名入口和下一步；未知如实标注。
4. 变更前后对照与影响；临期项目只在进入提醒阈值或发生变化时重复提醒，避免每日同内容刷屏。
5. 覆盖与失败说明、待核验清单、完整数据和日报文件链接。

所有计划来源检查成功且无事件时写“在本次已检查来源与窗口内，未发现新增符合条件项目”，附检查范围；不能声称全网无招标。当前任务要求每天推送则保留简短无新增回执；用户另有静默偏好时按其要求设置平台通知策略。

## 配置调度

在用户明确要求启用后，发现并使用当前环境的自动化工具（Codex 中先搜索 `automation_update`），检查已有同用途任务，优先更新而非重复创建。默认关联当前聊天；不得用 shell cron、后台常驻进程替代原生调度。按工具当前 schema 填写时区对应时间、频率、状态和提示词；创建返回成功后报告任务名、运行时间、范围、目的地和ID。工具不可用或失败时保留配置及提示词草稿，明确“未启用”，不宣称会自动推送。

给调度器的提示词应独立可执行，填入实际技能绝对路径和项目状态/输出绝对路径；不要仅写“按上文执行”，也不要填臆造工具名或不存在的文件。可以基于以下内容改写：

> 使用 $esg_bidding_summary（实际安装路径）执行每日中国大陆ESG、可持续发展与双碳采购监控。读取项目固定状态目录中的配置和上次成功检查点，自主联网覆盖全部核心主题、已配置延伸主题及官方/采购人/授权代理来源；保留重叠窗口并补查失败区间，核验原文、去重并跟踪更正、延期、终止。输出本次新增、补录、实质变更、临期和储备商机，列预算/限价、报名与文件获取截止、投标截止、资质要求、推荐理由和原文。主文优先可行动机会，附完整明细与覆盖说明。将报告存入实际输出目录，原子更新实际状态目录；没有新增与检索失败分别处理。将结果回复到当前聊天；本次只执行监控，不重新创建调度。

用户只要求当前扫描时，运行以上监控流程但跳过本节调度。测试技能也不要创建真实定时任务或发送测试邮件。
