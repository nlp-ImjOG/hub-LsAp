# ESG 月报 SKILL/AGENT 实施报告

> **作业来源**：第 16 周《Agent 应用部署：Skills 与 OpenClaw》homework1 / part1 · 案例一
> **编制日期**：2026-11-24
> **交付目标**：构建一个「ESG 月报」Skill，实现**自主搜索互联网 → 自主筛选信息 → 自主形成报告**的完整闭环，并以中国神华为示例实际运行完成案例。

---

## 一、项目概述

### 1.1 要解决的问题

ESG（环境 Environmental / 社会 Social / 治理 Governance）咨询场景中，客户需要按月获得一份覆盖**政策监管、行业动向、自身表现**三个层面的动态报告。传统人工编制需要分析师花费数天检索、交叉核对与撰写；本作业要求将这套工作沉淀为一个可复用的 **Claude Code Skill**，由 Agent 在一次会话内自主完成。

### 1.2 核心挑战

| 挑战 | 说明 | 应对思路 |
|---|---|---|
| 信息采集的广度与时效 | 月报要求"过去一个月"的时政信息，覆盖面横跨监管、行业、公司三个层面 | 设计三线并行的多组检索词扇出 + 原文抓取 |
| 信息的可信度 | 互联网来源良莠不齐，自媒体误读政策的情况常见 | 内置来源权威度分级与筛选规则 |
| 分析深度 | 作业明确要求"对 ESG 影响和建议"，不能只是新闻罗列 | 模板强制每条新闻落到"对客户的影响"，公司部分给可操作建议 |
| Skill 的通用性 | 以中国神华为示例，但 Skill 不应硬编码单一客户 | 参数化设计：客户名称、报告期均为输入项 |

### 1.3 运行环境与能力支撑

- 运行环境：Claude Code 会话，原生具备 `WebSearch`（联网检索）与 `WebFetch`（抓取原文）工具，**无需任何外部 API Key 或第三方依赖**；
- 报告期定义：以调用日为基准回溯一个月。本次示例运行日期为 **2026-11-24**，报告期约 **2026-10-24 ~ 2026-11-24**（2026 年 11 月刊）。

## 二、需求分析

### 2.1 原始需求

> 案例一：ESG 月报 SKILL/AGENT
> 汇总过去一个月的时政信息帮客户生成 ESG 月报。需要至少包括以下几个部分内容：
> 1. ESG 政策、评级、标准等相关的动态；
> 2. 客户所属行业层面相关的新闻动态，最佳实践；
> 3. 客户公司的一些动态对 ESG 影响和建议，对标企业的一些 ESG 关键行动。
> 可以以中国神华为例。
>
> 构建这个 skill，完成上述案例。skill 需要自主搜索互联网的内容，自主筛选信息，形成报告。希望最终报告得到的效果越好越好。

### 2.2 需求拆解

**（1）内容维度 —— 三大必需部分，映射到报告章节：**

| 需求条目 | 内容要点 | 对应报告章节 |
|---|---|---|
| ① ESG 政策、评级、标准动态 | 国内披露准则与监管新规（交易所可持续披露指引、国资委、财政部、证监会）；评级方法调整（MSCI、中证、Wind 等）；国际标准进展（ISSB、CSRD/ESRS、GRI） | 第一章 |
| ② 行业层面动态与最佳实践 | 煤炭/能源行业要闻；绿色矿山、CCUS、煤电联营、节能降碳改造；同业 ESG 报告发布、评级与奖项等最佳实践 | 第二章 |
| ③ 公司动态影响与建议 + 对标行动 | 中国神华近一月新闻/公告/项目 → ESG 三维度影响分析 → 可操作建议；对标企业（国家能源集团、中煤能源、陕西煤业、兖矿能源等）关键 ESG 行动 | 第三章、第四章 |

**（2）能力维度 —— 三个"自主"意味着：**

- **自主搜索**：检索策略（搜什么、去哪搜、搜多少）必须内置在 Skill 中，不能依赖用户喂料；
- **自主筛选**：时间窗匹配、来源分级、去重、相关性判断的规则必须显式写入 Skill；
- **自主成报**：报告结构、写作口径、质量标准必须以模板固化，保证每次产出稳定。

**（3）质量维度**："效果越好越好" → 将报告质量作为第一目标，通过**检索广度、分析深度、来源可溯、结构可读**四个抓手落实（详见第六章）。

## 三、总体设计

### 3.1 设计原则

1. **通用化优先**：Skill 以参数（客户名称、报告期）驱动，中国神华只是默认值与示例。遵循 skill-creator 规范"避免为眼前测试用例过拟合"；
2. **渐进式加载**：SKILL.md 控制在 500 行以内，只放工作流主干；检索词库、报告模板、对标清单等细节下沉到 `references/` 按需加载，并写明"何时读哪个文件"；
3. **过程可追溯**：检索笔记落盘为工作文件、每条信息标注来源与日期、报告附录给出完整来源清单——让"自主筛选"过程可被核验；
4. **零外部依赖**：仅使用 Claude Code 原生工具（`WebSearch` / `WebFetch` / `Write` / `Read`），在任何标准环境中均可运行。

### 3.2 技术架构与工作流

```
用户输入（客户名称?，报告期?）
        │
        ▼
┌─ Phase 0 输入解析 ─────────────────────────────┐
│ 确定客户/行业/报告期（默认：中国神华，近一个月）      │
│ 推断行业（中国神华 → 煤炭/能源）                   │
│ 创建输出目录 reports/，初始化检索笔记文件           │
└────────────┬───────────────────────────────────┘
             ▼
┌─ Phase 1 自主信息采集（三线并行）─────────────────┐
│ A 线  ESG 政策/评级/标准   4~8 组检索词，并行发起   │
│ B 线  行业动态/最佳实践    4~8 组检索词，并行发起   │
│ C 线  公司动态/对标企业    4~8 组检索词，并行发起   │
│ 关键命中 → WebFetch 抓原文补细节                │
│ 笔记随时落盘（标题/日期/URL/要点/可信度）           │
└────────────┬───────────────────────────────────┘
             ▼
┌─ Phase 2 自主筛选 ─────────────────────────────┐
│ 时间窗匹配 → 来源分级 → 去重 → 相关性过滤          │
│ 三线各保留 ≥5 条有效条目，不足则补检               │
└────────────┬───────────────────────────────────┘
             ▼
┌─ Phase 3 报告生成 ─────────────────────────────┐
│ 按 report-template.md 固定结构撰写               │
│ 每条新闻必落"影响点评"；公司部分给可操作建议          │
│ 跑质量自查清单 → 落盘 reports/*.md → 告知路径      │
└────────────────────────────────────────────────┘
```

## 四、Skill 详细设计

### 4.1 目录结构

```
part1/.claude/skills/esg-monthly-report/
├── SKILL.md                       # 主指令：frontmatter + 三阶段工作流（<500 行）
└── references/
    ├── search-playbook.md         # 三线检索词库、权威来源分级表、筛选规则
    ├── report-template.md         # 报告固定结构模板、各节写作要求、质量自查清单
    └── benchmark-companies.md     # 煤炭行业对标企业清单与各自关注要点
```

### 4.2 SKILL.md 设计

**Frontmatter（触发机制）：**

```yaml
---
name: esg-monthly-report
description: 汇总过去一个月的时政信息，为客户生成一份包含「ESG政策/评级/标准动态、行业动态与最佳实践、公司ESG影响分析与建议、对标企业关键行动」的ESG月报。当用户要求生成ESG月报/ESG周报/ESG定期报告，或提到"ESG动态汇总""ESG信息跟踪""帮我看看这个月ESG有什么新闻"，或想为某家公司（如中国神华）做ESG周期性跟踪时，务必使用本技能——即使用户没有明确说"生成月报"。适用客户默认为中国神华（煤炭/能源行业），报告期默认为近一个月。
argument-hint: "[客户名称] [报告期，可选]"
---
```

> description 写法遵循 skill-creator 规范：定义域 + 触发场景枚举 + "务必使用本技能——即使没明确说生成月报"的 pushy 措辞，避免 undertrigger。

**正文结构（约 200~300 行）：**

1. **一句话定位**：做什么、产出是什么、落盘到哪里（对齐输出期望）；
2. **输入解析规则**（Phase 0）：客户名/报告期的缺省规则、行业推断方法；
3. **三阶段工作流**（Phase 1~3）：每阶段为祈使句指令，说明 why（如"并行发起检索以减少总耗时""笔记落盘防止长会话上下文丢失"）；
4. **读取指引**：进入 Phase 1 前读 `references/search-playbook.md`；进入 Phase 3 前读 `references/report-template.md`；C 线检索对标企业时读 `references/benchmark-companies.md`；
5. **失败兜底**：检索无结果 / 原文抓取失败 / 报告期内信息量不足时的降级规则（不反复重试、交叉多源、放宽时间窗但必须标注数据日期）。

### 4.3 references/search-playbook.md 设计

**（1）三线检索词库（示例，实际文件中每线 8~12 组）：**

| 线 | 示例检索词 |
|---|---|
| A 政策/评级/标准 | 「上市公司 可持续披露 指引」「ESG 披露准则 新规 2026」「国资委 ESG 中央企业」「MSCI ESG 评级 方法 调整」「ISSB 准则 进展」「CSRD 实施」 |
| B 行业动态/最佳实践 | 「煤炭行业 ESG」「煤炭 绿色矿山 双碳」「煤电联营 / CCUS 煤炭」「能源集团 可持续发展报告」「煤炭 上市公司 ESG 评级」 |
| C 公司/对标 | 「中国神华 ESG」「中国神华 公告/绿色矿山/智能化」「中国神华 可持续发展报告」「中煤能源 / 陕西煤业 / 兖矿能源 ESG 行动」 |

**（2）来源权威度分级表：**

| 级别 | 来源类型 | 使用规则 |
|---|---|---|
| 一级（权威） | 监管机构官网（证监会、国资委、财政部、生态环境部）、交易所（上交所/深交所/港交所）、公司公告（巨潮资讯）、国际标准组织（ISSB、EFRAG、GRI） | 直接采用，可作报告主论据 |
| 二级（可信） | 主流财经媒体（新华社、证券时报、上证报、21 世纪经济报道、财新等）、行业媒体（中国煤炭报等） | 采用，关键数字尽量回溯一级源交叉验证 |
| 三级（低置信） | 自媒体、论坛、无署名转载 | 默认弃用；确有价值须标注"来源可信度低" |

**（3）筛选规则：** 时间窗（报告期内优先；评级/报告类数据可放宽但必须标注数据日期）→ 来源分级 → 去重（同一事件多源只保留最优来源）→ 相关性过滤 → 数量下限（三线各 ≥5 条，不足补检）。

### 4.4 references/report-template.md 设计

采用 skill-creator 官方推荐的 `## Report structure` 固定模板模式：

```markdown
# {客户名称} ESG 月报（{年月刊}）
报告期：{起} ~ {止}　|　编制：ESG 月报 Skill（AI 生成）　|　客户行业：{行业}

## 摘要
（150~300 字概括本期三大层面最重要的变化）

## 本月五大要点速览
| # | 要点 | 层面 | 对客户的意义 |

## 一、ESG 政策、评级与标准动态
### 1.1 国内政策与披露要求　### 1.2 评级动态　### 1.3 国际标准进展
> 每条格式：**[标题]**（日期，来源[编号]）—— 事实要点 + **对客户影响：** ……

## 二、行业动态与最佳实践
### 2.1 行业要闻　### 2.2 最佳实践案例（2~3 个，拆解做法与可借鉴点）

## 三、公司动态与 ESG 影响分析及建议
### 3.1 本期公司动态　### 3.2 ESG 影响分析（按 E/S/G 三维度）　### 3.3 建议行动（可落地）

## 四、对标企业 ESG 关键行动
### 4.1 关键行动对比表（企业 × 行动 × 亮点）　### 4.2 亮点解读与启示

## 附录
A. 信息来源清单（[编号] 标题 - 机构 - 日期 - URL）　B. 数据说明与免责声明
```

**各节写作要求**：每条新闻必须落到"对客户的影响"一句点评；第三章建议必须可落地（明确责任维度、动作、衡量方式），拒绝"加强重视"式空话；无法核实的内容不得写入正文。

**质量自查清单（生成报告后逐项核对）**：

- [ ] 三大必需部分齐全且各有 ≥5 条有效条目
- [ ] 每条信息有来源编号、日期，且附录来源清单完整可点击
- [ ] 报告期外的数据均已标注数据日期
- [ ] 第三章有 E/S/G 影响分析和 ≥3 条可操作建议
- [ ] 第四章有对标企业对比表与解读
- [ ] 摘要与五大要点速览与正文一致，无未标注的推测

### 4.5 references/benchmark-companies.md 设计

煤炭行业对标企业清单（含各自关注要点）：**国家能源集团**（母公司，一体化与绿色转型）、**中煤能源**（A+H，ESG 披露演进）、**陕西煤业**（智能化矿山标杆）、**兖矿能源**（海外布局与减碳）、**中国平煤神马 / 淮北矿业**等地方国企（转型样本）。每家列：披露情况、评级情况、标志性 ESG 项目、值得中国神华关注的差异点。该文件为 C 线检索提供"查谁、查什么"的靶点。

## 六、质量保障设计（回应"效果越好越好"）

| 抓手 | 具体机制 |
|---|---|
| 检索广度 | 三线 × 每线 4~8 组不同角度检索词，同一批独立检索**并行发起**减少耗时；关键命中用 `WebFetch` 抓原文而非只看搜索摘要 |
| 分析深度 | 模板强制每条新闻落"对客户影响"点评；公司部分按 E/S/G 三维度拆解影响并给可落地建议；对标部分给结构化对比 + 启示解读 |
| 来源可信 | 来源三级分级、关键数字交叉验证、报告期外数据强制标注、低置信来源默认弃用 |
| 结构可读 | 摘要 + 五大要点速览表（30 秒读完本期）；对标对比表；完整附录来源清单可追溯 |
| 过程可靠 | 检索笔记随时落盘防长会话上下文丢失；数量下限不足自动补检；失败兜底规则避免无效重试 |
| 收尾把关 | 报告生成后逐项跑质量自查清单，不合格先修复再交付 |

## 八、风险与应对

| 风险 | 影响 | 应对措施 |
|---|---|---|
| WebSearch 对中文信源覆盖不足或结果偏英文 | 信息量不够、错过国内政策 | 检索词中英双语并行；`WebFetch` 直访权威站点（监管官网、交易所、巨潮资讯、公司官网）的检索页与已知页面 |

| 评级/评级方法类数据天然不在月度窗口内 | 与"过去一个月"冲突 | Playbook 明确规则：此类数据可放宽时间窗，但必须标注数据日期与口径 |
| 长会话上下文被压缩导致信息丢失 | 报告前后不一致、来源丢失 | 检索笔记即时落盘 `reports/notes-<客户>-<期>.md`，成报时以笔记文件为准 |
| 个别原文页面抓取失败（反爬/超时） | 细节缺失 | 兜底规则：换源交叉验证，不反复重试同一 URL；抓不到就用搜索摘要并标注信息完整度受限 |
| AI 生成内容的事实性风险 | 报告误导使用者 | 只写有来源支撑的事实；推测性内容显式标注；附录加免责声明（AI 生成、供参考、不构成投资/合规建议） |
