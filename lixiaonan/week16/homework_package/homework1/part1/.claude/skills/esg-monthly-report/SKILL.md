# ESG 月报生成

你现在的任务：通过自主搜索互联网，为指定客户编制一份覆盖**政策 / 行业 / 公司**三个层面的 ESG 月报，落盘为 Markdown 文件。产出质量重于速度——报告要能直接交付给客户的 ESG 负责人阅读。

最终产物（相对当前工作目录）：
- 报告：`reports/<客户名称>_ESG月报_<YYYY-MM>.md`
- 过程笔记：`reports/notes-<客户名称>-<YYYY-MM>.md`

## Phase 0：输入解析

1. **客户名称**：取第一个参数；未提供时默认「中国神华」。
2. **报告期**：取第二个参数或用户自然语言中的时间表达；未提供时以今天为基准回溯一个月（约滚动 30 天）。报告期命名为 `<YYYY>年<M>月刊`。
3. **行业推断**：中国神华 → 煤炭/传统能源。其他客户若无法确定行业，先检索「<客户名称> 主营业务 行业」确认——行业决定 Phase 1 的 B 线检索词与对标企业选择。
4. **工作目录准备**：`reports/` 不存在则创建；初始化笔记文件 `reports/notes-<客户名称>-<YYYY-MM>.md`，头部写入客户、行业、报告期三行。

把确定好的客户/行业/报告期清楚记录在笔记文件头部——后面所有检索与写作都以它为准。

## Phase 1：自主信息采集

**先读 `references/search-playbook.md`**——三线检索词库、权威来源分级、笔记格式都在里面，不要凭空想检索词。

按三条信息线并行采集（同一批相互独立的检索放在一次消息中并行发起，比串行快得多）：

- **A 线 · ESG 政策/评级/标准**：国内披露准则与监管、评级动态、国际标准进展
- **B 线 · 行业动态/最佳实践**：客户所在行业的要闻与优秀实践
- **C 线 · 公司与对标**：客户公司近期动态；对标企业 ESG 关键行动（检索对标企业前读 `references/benchmark-companies.md`，里面有"查谁、查什么"）

执行要求：

1. 每线从 playbook 中挑 4~8 组**不同角度**的检索词。角度重复的检索词只会带回重复结果，浪费轮次。
2. 对值得写进报告的命中，用 `WebFetch` 抓原文补齐细节（日期、数字、适用范围）。只看搜索摘要容易遗漏关键限定条件，也会放大转述误差。
3. 每条有价值的发现**立即追加**到笔记文件（格式见 playbook）。笔记落盘的原因：长会话中上下文可能被压缩，成报时以笔记文件为准，而不是依赖记忆。
4. 每线至少收集 5 条候选（未经筛选的原始发现），不足就换角度补检。

## Phase 2：自主筛选

按 playbook 中的筛选规则处理笔记：时间窗匹配 → 来源分级 → 去重 → 相关性过滤。

- 同一事件多源报道时只保留来源级别最高、细节最全的一条，其余在笔记中注明"并入#"备查；
- 每条信息在笔记中标记「入选」或「落选+原因」。这不是流程仪式——报告附录的来源清单与争议数据回溯都依赖笔记；
- 筛选后三线各保留 ≥5 条有效条目。仍不足的线回到 Phase 1 用新角度补检，而不是降低标准硬凑。

## Phase 3：报告生成

**先读 `references/report-template.md`**，严格按其中的 Report structure 模板撰写，落盘到 `reports/<客户名称>_ESG月报_<YYYY-MM>.md`。

写作纪律（模板中有详细要求）：

- 每条新闻必须落到「**对客户影响：**」点评——客户要的是分析，不是新闻转载；
- 第三章建议必须可落地（动作 + 衡量方式），拒绝"加强重视""持续关注"式空话；
- 只写有来源支撑的事实，推测性内容显式标注"推测"；报告期外的数据必须标注实际数据日期；
- 用 [编号] 引用来源，与附录 A 的来源清单一一对应。

写完后**逐项执行模板末尾的质量自查清单**，任何一项不达标先修复再交付。完成后向用户报告：文件路径、三大层面各多少条有效信息、来源总数。

## 失败兜底

- **中文结果太少**：检索词中英双语并行；或按 playbook 的直访站点清单用 `WebFetch` 抓权威站点；
- **单个 URL 抓取失败**：换源交叉验证即可，不要对同一 URL 反复重试——抓取失败很正常，不值得耗时；
- **报告期内公司新闻偏少**（单一公司月度信息天然有限）：放宽到公告、评级调整、项目投产等动态，如实标注日期；用行业事件与对标企业行动补齐分析厚度。宁缺毋滥，不要为凑数把弱相关信息塞进报告；
- **检索工具不可用**：立即告知用户环境限制，不要编造信息。宁可产出一份"信息受限"的说明，也不能虚构新闻。
