# 字段抽取与规范化规则

**何时读**：Phase 2 逐条处理公告前读本文件。原则：错误数据比缺失数据危害大——字段不确定就置 null，绝不猜测。

## 18 字段模型（data/bids.jsonl 每行一条 JSON）

| 字段 | 必填 | 说明与取值 |
|---|---|---|
| record_id | ✔ | 去重指纹，见下节 |
| project_name | ✔ | 项目名称；去括号补充说明、全半角统一、去多余空格 |
| stage | ✔ | 招标公告 / 更正公告 / 中标公告 / 成交结果 / 入围公示 |
| theme | ✔ | 主题标签数组（可多选），取值见 keywords.md 五大主题 |
| industry_type | ✔ | 咨询服务 / 信息化系统 / 工程建设 / 设备采购 / 运营服务 / 认证核查 / 培训宣传 / 其他 |
| buyer | ✔ | 采购人 / 招标人全称 |
| buyer_type | ✔ | 政府机关 / 事业单位 / 国企 / 高校 / 上市公司 / 民企 / 其他（按采购人性质判断） |
| winner |  | 中标人/成交供应商；仅成交侧公告有，招标阶段为 null |
| amount_wan |  | 金额（万元，float）；语义见金额规范化表 |
| amount_raw |  | 原文金额表述原样保留，供复核 |
| region | ✔ | 省/直辖市；能判断到市则填"省+市" |
| publish_date | ✔ | 公告发布日期 YYYY-MM-DD |
| deadline |  | 投标/递交截止时间，仅招标侧公告 |
| source_name | ✔ | 来源平台名称 |
| source_level | ✔ | 1/2/3，见 search-playbook 分级 |
| url | ✔ | 公告链接 |
| summary | ✔ | 一句话摘要（≤60 字），写事实不写评价 |
| collected_at | ✔ | 采集时间 ISO8601 |

## record_id 去重指纹

```
规范化项目名 = project_name 去空格、全半角统一、去括号内补充说明
record_id = sha1(规范化项目名 + buyer)[:12]
```

- 新指纹 → 追加入库
- 已存在指纹：
  - stage 升级（招标公告 → 中标公告/成交结果）→ 更新原记录 stage/winner/amount_wan，**不新增行**
  - 同 stage 重复 → 跳过
- URL 相同亦判重（防止同一公告被不同关键词命中时误判为两个项目）

## 金额规范化表（统一万元）

| 原文写法 | amount_wan | 备注 |
|---|---|---|
| 中标金额：1,285,000 元 | 128.5 | 元 → 万元 ÷10000 |
| 成交金额为 365.8 万元 | 365.8 | |
| 中标价 1.2 亿元 | 12000.0 | 亿 → 万元 ×10000 |
| 预算金额：450 万 | 450.0 | stage 仍为招标公告；此为预算而非成交价 |
| 最高限价 80 万元，未披露成交价 | 80.0 | summary 注明"限价口径" |
| 中标折扣率 85%（无绝对金额） | null | 框架协议常见，金额缺失 |
| 无金额 / 具体面议 | null | amount_raw 保留原文 |

**金额口径优先级：成交/中标价 > 预算金额 > 最高限价。** 中标公告里同时出现预算与成交价时，取成交价，预算价放 summary。

## 抽取优先级与核验要求

1. 公告正文（WebFetch 抓到的原文）> 搜索摘要 > 标题
2. **金额必须与中标人同段核实**："XX公司以XX万元中标"是可信表达；金额与中标人分属两段且无法对应时，该金额不入库
3. 无法确认的字段置 null；每条记录必须带 url 与 publish_date，缺任一则不入库
4. 抓取失败仅有摘要时：入库但 summary 末尾标注"（据搜索摘要，原文未核验）"
