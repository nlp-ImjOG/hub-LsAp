# 交付前质检清单

> 逐条打勾，任何一条不过就回去改。**不要交带占位符的报告。**

## 一、五条硬性质量线

| # | 检查项 | 通过标准 | 常见失败 |
| --- | --- | --- | --- |
| 1 | 时效 | 所有条目落在统计期内；期外内容标注"（背景）"并注明原发布时间 | 把 3 个月前的旧闻当本月动态 |
| 2 | 可核验 | 每条事实有来源机构 + 日期 + 链接；判断句标注"（分析）" | 有一半条目无引用 |

| 4 | 有量化 | 能用数字的地方都用了数字 | "大幅提升""显著改善" |
| 5 | 可执行 | 建议写到"做什么 / 谁做 / 何时前完成" | "建议加强 ESG 管理" |

## 二、结构与内容

- [ ] 十节结构完整（报头、KPI、要点、政策、行业、公司、对标、下月关注、附录 A/B、附录 C/D）
- [ ] "本月要点"5 条，每条末尾有判断而不只是描述
- [ ] 政策章节区分 **征求意见 / 已发布 / 已施行 / 截止日** 四种状态
- [ ] 政策日历表列出统计期后 6 个月内的关键节点
- [ ] 影响评估表每条都含"责任部门 + 时间节点"
- [ ] 对标表维度固定（排放总量、强度、范围三、财务量化、技术路径、管理机制、评级）

- [ ] "下月关注"每条带具体日期
- [ ] 附录 D 写明限制（数据来源口径、缺失项、未估算项）

## 三、数字自检

- [ ] 每个百分比的分子分母都能说清
- [ ] 同比/环比的基期明确
- [ ] 强度指标的分母（收入/产量）口径一致
- [ ] 跨章节同一指标数值一致（如排放总量在 KPI、正文、对标表三处相同）
- [ ] 单位统一（万吨 CO₂e、万元、吨/万元收入），不混用"亿吨""万吨"
- [ ] 时间表述统一（正文用 `2026-11-18`，叙述用"11 月 18 日"）

## 四、引用与脚本质检

```bash
python scripts/build_report.py report.md --check --strict
```

- [ ] 返回 0 个错误（正文引用编号与来源表一一对应）
- [ ] 无"来源定义但正文未引用"的冗余条目
- [ ] 无占位符（待补充 / TODO / TBD / XX）
- [ ] `--html` 生成成功，浏览器打开无乱码、表格不溢出
- [ ] HTML 中无残留 Markdown 符号（`**`、行首 `|`、`##`）

快速自检（渲染后）：

```bash
python - <<'PY'
import re
h = open('report.html', encoding='utf-8').read()
print({'tables': h.count('<table>'), 'h2': h.count('<h2'),
       'raw_pipe': len(re.findall(r'^\|', h, re.M)), 'bold': h.count('**')})
PY
```

`raw_pipe` 与 `bold` 必须为 0。

## 五、常见内容事故

| 事故 | 后果 | 预防 |
| --- | --- | --- |
| 把"征求意见稿"写成"已发布" | 误导客户按未生效规则行动 | 状态列必填，四态区分 |
| 跨评级体系比高低 | MSCI 的 BB 与中证的 AA 不可比 | 只在同一体系内做同业对比 |
| 用互动平台问答当事实 | 引用了未经证实的承诺 | 标注为"投资者关注点" |
| 同业减排比例直接对比 | 边界不同（含不含范围三）结论反转 | 标注口径差异 |
| 用第三方解读代替原始报告 | 数字被二手加工 | 关键数字回查原文，注明"以报告原文为准" |
| 强度改善当作绝对减排 | 收入上升会稀释强度 | 同时报总量与强度 |
